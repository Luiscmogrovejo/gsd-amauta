# Test-only dependencies for CI (plan 88-08; extended by plan 88-16-07). Runtime
# dependencies stay in requirements.txt; nothing here ships. Every version is
# pinned EXACTLY — the repository's supply-chain rules forbid `^` and `~`, and a
# range on a test dependency is how a green suite turns red overnight.
#
# BOTH CI jobs install this file. The `pytest` job installs it beside
# requirements.txt; the Node `test` job installs ONLY this file, because its
# tests shell out to services/*.py and need the same interpreter to have the
# packages those modules import. That is why pyyaml, pydantic and
# psycopg2-binary appear here as well: installing from one file is what keeps
# the CI environment and a developer's from drifting.
#
# Supply-chain figures, measured 2026-11-12 (PyPI JSON + pypistats):
#   pytest           weekly 100M+      last release well over 7 days old
#   numpy            weekly 275,310,907   2.4.3 predates 2.5.4 (2026-10-10)
#   mcp              weekly  79,134,034   checked 2026-11-11 (plan 88-08)
#   pyyaml           weekly 298,814,955   6.0.3 released 2025-09-25
#   pydantic         weekly 278,737,500   2.14.2 released 2026-10-29
#   psycopg2-binary  weekly  54,722,375   2.9.9 mirrors requirements.txt
#   semgrep          weekly   5,557,833   1.183.0 released 2026-10-29
# Every one clears "more than 1,000 weekly downloads" and "not published within
# the last 7 days" by a wide margin.
pytest==9.0.2
numpy==2.4.3
# requirements.txt leaves mcp unbounded above, so a fresh runner resolves mcp 2.x.
# services/amauta-mcp.py is written against the 1.x server API (`@server.list_tools()`
# decorators); under 2.x it dies at import, so the MCP test modules either skip
# without saying why or fail. Pin the suite to the version the code is developed and
# verified against. Weekly downloads checked 2026-11-11: 79,134,034.
mcp==1.27.1

# ── Imported by services/*.py that the NODE tests drive as subprocesses ──────
# services/module_lifecycle.py `compute_manifest_hash` requires PyYAML; without
# it nine cases in module-lifecycle-cli/-e2e and one in 88-12-agent-yaml-parses
# skipped. services/module_schema.py validates with pydantic.
pyyaml==6.0.3
pydantic==2.14.2
# MUST equal the pin in requirements.txt — tests/88-16-requirements-pins.test.cjs
# fails if the two ever disagree. services/complexity_scorer.py and the
# migration runner need it, and tests/86-01-dsn-containment.test.cjs skipped
# three cases purely because it was not importable.
psycopg2-binary==2.9.9
