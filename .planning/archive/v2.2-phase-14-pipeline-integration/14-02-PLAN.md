# Plan 14-02: MCP Auto-Registration + System Health Dashboard

## Objective

Register the existing MCP server in `~/.claude/settings.json` during the install flow so Claude Code
agents can discover GSD-Amauta tools natively, and enhance the `amauta status` health dashboard to
show comprehensive system health including embedding coverage, SKB size, RLM cache stats, agent
performance summary, and task queue depth. After this plan, the MCP server is automatically available
after install and the health dashboard gives a complete picture of system health.

## Context

- **WIRE-01:** bin/mcp-server.cjs exists with 6 tools (memory-search, memory-store, task-list,
  task-status, rpetd-log, system-status) but is NOT registered in `~/.claude/settings.json`. The
  `mcpServers` section does not exist. cli.cjs lines 30-44 have a manual `mcp register` command that
  shells out to `claude mcp add`, but this requires the claude CLI to be installed and is never run
  during `npx gsd-amauta init`.

  The fix: in install.js, during the Claude Code runtime install flow, add an `mcpServers` entry
  to settings.json with the correct stdio transport config. This must handle: (1) no settings.json,
  (2) settings.json without mcpServers, (3) settings.json with existing mcpServers (add ours),
  (4) settings.json already has gsd-amauta (skip/update).

  install.js already has `readSettings()` (line 248) and `writeSettings()` (line 262) helpers, and
  already manipulates settings.json for hooks and statusline (lines 2232-2326). The MCP registration
  slots in naturally next to the hook configuration.

- **WIRE-04:** `amauta status` (no args) routes via cli.cjs line 81-85 to gsd-memory.cjs `cmdStatus()`
  (line 1364). The current status output shows: backend, PG host, features, embeddings, memories,
  distillation, tags, tasks, daemon info, and RLM info.

  What's missing: embedding coverage % (how many memories have embeddings), SKB entry count,
  agent performance summary (per-agent pass rates), PG sync health (any recent mirror failures),
  and research chain provider availability.

  The daemon `/health` endpoint already returns most base data. The daemon `/api/infra` endpoint
  returns task_counts. We need to query `/api/agent-performance` for each known agent type and
  `/api/skb/list` for SKB count. For embedding coverage, we need to add a simple check to the
  daemon health or use an existing endpoint.

## Phase Success Criteria (must_haves for this wave)

1. After `npx gsd-amauta init --claude --global`, settings.json contains `mcpServers.gsd-amauta`
2. The MCP entry uses `command: "node"` and `args: ["<path-to-mcp-server.cjs>"]` with correct path
3. If mcpServers.gsd-amauta already exists, install updates the args path (idempotent)
4. If mcpServers section has other servers, they are preserved untouched
5. Non-Claude runtimes (opencode, gemini, codex) skip MCP registration (MCP is Claude Code only)
6. `amauta status` shows: embedding coverage %, SKB entry count, agent performance summary
7. `amauta status` shows task queue depth (pending + in-progress + validation counts)
8. `amauta status --json` includes all new fields in the JSON output
9. All existing tests pass unchanged

## Risks

1. **settings.json corruption:** Malformed JSON write could break Claude Code. Mitigation: install.js
   already uses `readSettings()`/`writeSettings()` pattern safely. The MCP entry is a simple object.
2. **Path resolution for MCP server:** The path to mcp-server.cjs must be absolute and correct.
   Mitigation: Use `path.resolve(__dirname, 'mcp-server.cjs')` which is the same pattern used by
   cli.cjs line 28.
3. **Agent performance endpoint returns different format:** The daemon endpoint returns different
   fields depending on data availability. Mitigation: Use safe defaults (`pass_rate: N/A` if no data).
4. **Backward compatibility:** Older daemon versions may not have all endpoints. Mitigation: Each
   additional status section is wrapped in try/catch (existing pattern in cmdStatus).
5. **MCP registration for local installs:** For `--local` installs, the settings.json is in the
   project directory `.claude/settings.json`. The MCP server path needs to be correct for that context.
   Mitigation: Use the same `isGlobal` path resolution already used for hooks.
