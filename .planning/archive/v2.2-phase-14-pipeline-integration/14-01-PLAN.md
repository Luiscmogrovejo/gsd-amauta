# Plan 14-01: Performance Routing + Dual-Write Alerting

## Objective

Wire agent performance data into task routing as a tiebreaker (execute-phase.md), and surface PG
dual-write failures in the daemon HTTP response so agents see `[PG_SYNC_WARN]` in their stdout
instead of the failure being silently logged to daemon stderr. These are two surgical changes that
close the gap between data collection and actionable visibility.

## Context

- **WIRE-02:** execute-phase.md lines 112-120 route tasks to executor agents purely by file pattern
  matching (.tsx -> frontend, .py -> backend, etc.). Agent performance data exists in the
  `gsd_agent_performance` table and is already queryable via `GET /api/agent-performance?agent_id=X`,
  but this data is NEVER used in routing decisions. At claim-time, `_agent_performance_summary()` in
  amauta.py:733-745 injects advisory text, but the execute-phase workflow ignores it entirely.

  The fix is a prompt-level change: after determining EXECUTOR by file pattern, query the daemon for
  the chosen executor's pass rate. If pass rate < 70% AND an alternative executor exists with > 85%
  pass rate for that domain, prefer the alternative. This uses `curl` to the daemon -- no Python changes.

- **WIRE-03:** services/amauta-daemon.py lines 994-1020 contain the dual-write mirror code. When PG
  mirror fails, `log.warning()` is called (line 1018) but the HTTP response at line 1020 returns
  `{"output": out, "error": err, "exit_code": rc}` with NO indication of the mirror failure. The
  agent sees a successful response and assumes PG is in sync.

  The fix: catch the mirror exception, append `\n[PG_SYNC_WARN] PG mirror failed: {error}` to the
  `out` string before sending the response. The CLI (gsd-amauta.cjs) already prints `data.output` to
  stdout (line 256), so the warning will be visible to agents without any CLI changes.

## Phase Success Criteria (must_haves for this wave)

1. execute-phase.md routing block queries agent performance after file-pattern determination
2. When pass rate < 70%, routing considers executor-general as a fallback (logged as override)
3. Performance query failure (daemon down) does NOT block routing -- falls back to file pattern only
4. PG dual-write failures append `[PG_SYNC_WARN]` to the response `output` field
5. The warning includes the exception type/message for diagnosability
6. Successful PG mirror writes do NOT add any output (zero noise on happy path)
7. All existing tests pass unchanged

## Risks

1. **Daemon unavailable during routing:** `curl` to daemon may timeout. Mitigation: 2s timeout with
   fallback to pure file-pattern routing (current behavior). The `|| true` pattern ensures no breakage.
2. **Performance data insufficient:** New agents have 0 tasks tracked. Mitigation: Only apply
   performance tiebreaker when agent has >= 5 historical tasks (avoid penalizing new agents).
3. **PG_SYNC_WARN noise:** If PG is persistently down, every mutation prints a warning. This is
   intentional -- the user should know. But it won't break anything since it's appended after the
   actual command output.
4. **Prompt-level changes harder to test:** execute-phase.md is a workflow prompt, not executable code.
   Mitigation: the change is additive bash that can be verified by visual inspection + integration test.

```python
"""Test that PG_SYNC_WARN marker appears in daemon response on mirror failure."""
import unittest

class TestPgSyncWarn(unittest.TestCase):
    def test_pg_sync_warn_format(self):
        """Verify the warning string format matches what the CLI grep expects."""
        error_msg = "connection refused"
        task_id = "TK-0001"
        warning = f"\n[PG_SYNC_WARN] PG mirror failed for {task_id}: {error_msg}"
        self.assertIn("[PG_SYNC_WARN]", warning)
        self.assertIn(task_id, warning)
        self.assertIn(error_msg, warning)
        self.assertTrue(warning.startswith("\n"))

    def test_empty_warning_on_success(self):
        """Verify no warning text is added on successful mirror."""
        out = "TK-0001 status changed to in-progress"
        pg_sync_warning = ""  # success path
        result = out + pg_sync_warning
        self.assertNotIn("[PG_SYNC_WARN]", result)
        self.assertEqual(result, out)

    def test_warning_appended_to_output(self):
        """Verify warning is appended (not prepended) to preserve command output."""
        out = "TK-0001 status changed to in-progress"
        pg_sync_warning = "\n[PG_SYNC_WARN] PG mirror failed for TK-0001: connection refused"
        result = out + pg_sync_warning
        self.assertTrue(result.startswith("TK-0001"))
        self.assertTrue(result.endswith("connection refused"))
        self.assertIn("[PG_SYNC_WARN]", result)

if __name__ == "__main__":
    unittest.main()
```
