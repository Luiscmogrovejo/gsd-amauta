# Plan 14-02 — Dedup Bypass + Pass 0 Validation Engine

## Goal

Build the two foundational pieces that Pass 1+2 (Plan 14-03) needs: (a) the
scoped dedup bypass in amauta.py + CJS flag pass-through so plan-to-tasks can
create tasks without hitting the similarity guard, and (b) the Pass 0
validation engine in gsd-tools.cjs that catches cycles, caps, schema errors,
and agent-assignment conflicts BEFORE any task is created. All unit tests for
Pass 0 logic ship with this plan.

## Scope

- `amauta.py`: patch `_dedup_check()` with scoped bypass, add `--source` and
  `--from-plan` to `cmd_add` argparse.
- `gsd-amauta.cjs`: add `--source` and `--from-plan` flag pass-through in
  `cmdAdd`.
- `gsd-tools.cjs`: add `planToTasks()` function with full Pass 0 logic (XML
  parsing, cycle detection, cap counting, schema validation, agent-assignment
  conflict detection, files-disjoint split algorithm), `case 'plan-to-tasks':`
  dispatch entry, and `module.exports` additions.
- `tests/14-plan-to-tasks.test.cjs`: unit tests (~12-15 cases) for Pass 0
  logic — no daemon needed.

## Must-Haves

- [ ] `_dedup_check` scoped bypass works: same plan_id tasks with 90% title
      similarity both create; different plan_id triggers dedup; manual add
      triggers dedup.
- [ ] `--source` and `--from-plan` flags are accepted by `amauta add task`.
- [ ] `gsd-amauta.cjs cmdAdd` passes both new flags through to daemon and
      direct CLI paths.
- [ ] `planToTasks()` Pass 0 rejects cyclic dependencies with hard error and
      zero task creation.
- [ ] `planToTasks()` Pass 0 rejects plans exceeding 10-task cap with
      structured JSON guidance including `suggested_split_index`.
- [ ] `planToTasks()` Pass 0 rejects plans missing `<story>` block.
- [ ] `planToTasks()` Pass 0 detects agent-assignment conflicts via
      `routeExecutor()`.
- [ ] `planToTasks()` is exported behind `require.main !== module` guard.
- [ ] All Pass 0 unit tests pass.
- [ ] `GSD_P_AUTO_TASK=false` causes `planToTasks()` to exit early with
      warning.

    **Pass 0 validation functions (each a separate helper, all exported):**

    1. `_validatePlanShape(planContent)` — returns `{valid, errors: []}`:
       - Check `<story>` block exists (reject if missing)
       - Check every `<task>` has `<agent>`, `<files_expected>`, `<acceptance_criteria>`

    2. `_detectCycles(tasks)` — returns `{hasCycle, cycle: []}`:
       - Build adjacency list from `depends_on` fields
       - DFS-based cycle detection (standard Kahn's algorithm or recursive DFS with visited/inStack sets)
       - If cycle found, return the cycle participant IDs (e.g. `["14-02-01", "14-02-03", "14-02-01"]`)

    3. `_checkAgentConflicts(tasks)` — returns `{conflicts: []}`:
       - For each task: compute `routeExecutor(union of files_expected.modify + files_expected.create, comma-joined)`
       - Compare result against the `<agent>` field from the plan
       - If mismatch: add to conflicts array with `{taskId, planAgent, computedAgent, files}`

    4. `_filesDisjointSplit(tasks)` — returns `{suggested_split_index, split_rationale, new_plan_files: []}`:
       - Walk the task list forward, maintaining a running set of files touched (modify + create)
       - At each index i, check if the files in tasks[0..i] are disjoint from files in tasks[i+1..N]
       - If a fully disjoint boundary exists, return the index with `split_rationale: "disjoint_at_N"`
       - If NO fully disjoint boundary exists, compute the overlap count at each candidate index and return the index with the LEAST overlap: `{suggested_split_index: N, split_rationale: "least_overlap_at_N", overlap_count: M}`. This handles the partial-overlap case (CONTEXT.md Area 3 case 2).
       - If files overlap with everyone at every possible cut (i.e., all tasks touch the same file), return `{suggested_split_index: null, split_rationale: "no_disjoint_prefix"}`

    5. `_renderDagText(tasks)` — returns string, max 500 chars:
       - ASCII rendering: each task on a line, arrows for deps (e.g. `14-02-01 -> 14-02-02`)
       - If result exceeds 500 chars, truncate with `...` and append `(full DAG in sidecar file)`

    6. `_diffPlanVsAmauta(planTasks, amautaTasks)` — returns `{drifted, divergence_type, diffs: []}`:
       - Compare structural fields only: `title`, `agent`, `files_expected.modify`, `files_expected.create`, `files_expected.delete`, `depends_on`
       - NOT compared: `read_first`, `action`, `acceptance_criteria`
       - Each diff entry: `{taskId, field, planValue, amautaValue}`
       - If `drifted: true`, set `divergence_type: "plan_amauta_drift"` (matches the v1.1.0 enum value for downstream consumers and explicit test assertion)

    - Run `_detectCycles` — hard error if cycle found

      `{error: "cap_exceeded", cap: 10, actual: N, suggested_split_index, split_rationale, new_plan_files}`
    - Run `_checkAgentConflicts` — if any conflict, halt with `agent_assignment_conflict` divergence
    - **Pass 0 complete.** Return parsed plan structure for Pass 1+2 (Plan 14-03).
    - For now, Pass 1+2 are stubs that return `{pass0: "complete", tasks: parsedTasks, story: parsedStory}`.
