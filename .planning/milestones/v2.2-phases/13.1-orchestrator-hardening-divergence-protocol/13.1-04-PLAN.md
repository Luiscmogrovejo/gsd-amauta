# Plan 13.1-04 — HARDEN-04 Validator `--gaps-found` CLI + Gaps Report + Routing

## Goal

Add the `--gaps-found` flag to the validator CLI (third verdict, exit code 2),
write a structured gaps report on gaps-found verdicts, and wire orchestrator
routing branches in the execute-phase workflow. This is the mechanical half of
HARDEN-04; the vocabulary-lock markdown edits to `gsd-validator.md` live in
plan 13.1-03.

## Scope

- `get-shit-done/bin/gsd-amauta.cjs` — `cmdValidate` at ~line 1024 gains
  `--gaps-found` flag (exit code 2).
- Gaps report JSON at `.planning/milestones/<phase>/gaps-report-<timestamp>.json`
  with schema: `gaps[]` (each tied to `requirement_id`),
  `non_gaps_observations[]` pressure-release array, `phase`, `timestamp`. NO
  severity tagging within the gaps array.
- Orchestrator routing branches in `execute-phase.md`:
  - `pass` (exit 0) → phase advances, roadmap updated
  - `gaps_found` (exit 2) → phase does NOT advance; re-route to re-planning
    (delta plan); mini-wave + re-validation; no retry counter
  - `fail` (exit 1) → phase does NOT advance; roadmapper invoked; human
    escalation; no auto-retry
- Auto-escalation separation: `gaps_found` does NOT count as failure; track
  `gaps_rate_per_phase` separately; `fail` counts toward the 3-consecutive
  rule.
- Backward compatible: `--pass` and `--fail` unchanged.

## Must-Haves

- [ ] `cmdValidate` in `gsd-amauta.cjs` accepts `--gaps-found`.
- [ ] `node get-shit-done/bin/gsd-amauta.cjs validate --gaps-found; echo $?`
      prints exactly `2`.
- [ ] `--pass` and `--fail` behavior unchanged (exit 0 and 1 respectively).
- [ ] Gaps report written to
      `.planning/milestones/<phase>/gaps-report-<timestamp>.json` on
      `--gaps-found`.
- [ ] Gaps report schema: `{phase, timestamp, gaps: [], non_gaps_observations: []}`.
- [ ] Each gap has a `requirement_id` field.
- [ ] `execute-phase.md` documents the 3 routing branches.
- [ ] No `severity` field on gaps (explicitly forbidden).

## Risks

1. **Mutual-exclusion check** — `--pass --fail --gaps-found` combinations must
   be rejected. A regression here would let callers pass multiple flags and
   get undefined behavior. Test all 3 pairs plus all-3 in verification.
2. **Gaps report path collision** — timestamp resolution must be sufficient
   (ISO8601 with milliseconds or add a pid suffix) to avoid collision when the
   validator runs twice in the same second.
3. **Mini-wave recursion** — the `gaps_found` → re-plan → mini-wave loop has
   no retry counter by design. If a planner keeps producing gappy plans, the
   loop never terminates. This is deliberate per CONTEXT.md ("no retry
   counter") but surfaces as a human-visible pattern. Not a code risk — a
   process risk. Flagged for operator awareness only.
4. **Exit code 2 conflict** — some Unix tools reserve exit 2 for "command-line
   argument error." The validator's exit 2 is for `gaps_found`. Shell wrappers
   that distinguish "bad args" from "gappy phase" must key off the printed
   output, not the exit code alone. Document in the routing section header.
