# Plan 13.1-02 — HARDEN-02 Divergence Protocol Reference File

## Goal

Create the shared behavioral protocol reference file that tells the 4 executors
and the validator exactly what to do when observed state contradicts a task
brief. This is the behavioral half of the Phase 13 defense: HARDEN-01 halts the
wave deterministically; HARDEN-02 tells the agent what to do instead of
silently "fixing" it.

The single output is `get-shit-done/references/divergence-protocol.md` — a
runtime Read reference (same pattern as `qa-checklist.md`, `creative-research.md`).
Agent `.md` files that reference it land in plan 13.1-03.

## Scope

- New file `get-shit-done/references/divergence-protocol.md` with
  `version: "1.0.0"` at the top.
- Complete decision tree: 4 orchestrator options (re-route, re-plan, expand
  scope, halt phase). No "ignore and proceed."
- Full divergence_report JSON schema with every mandatory field, including
  `rationalization_check` as MANDATORY (omission never valid).
- `work_in_progress_state` sub-schema for mid-execution divergences.
- `assumption_check_completed_at` / `first_modification_at` ordering fields.
- Exit code 87 fallback for report-write failure with structured stderr
  contract.
- Validator variant with `verdict_ambiguity` divergence_type and constrained
  reconciliation options.
- Report location contract:
  `.planning/milestones/<phase>/divergence-reports/<task_id>-<timestamp>.json`.

## Must-Haves

- [ ] File exists at `get-shit-done/references/divergence-protocol.md`.
- [ ] First non-blank line contains `version: "1.0.0"`.
- [ ] Decision tree enumerates exactly 4 orchestrator options.
- [ ] `rationalization_check` field is documented as MANDATORY with the
      "I considered just fixing it because [reason]" example text.
- [ ] `work_in_progress_state` sub-schema enumerates 5 fields.
- [ ] Exit code 87 documented with stderr fallback contract.
- [ ] Validator variant section exists with `verdict_ambiguity`.
- [ ] Report path template is documented.

    Body sections (in order):

    1. **Title + framing** — "Divergence Protocol" with a blockquote explaining runtime Read usage and the binary-trigger rule.

    2. **When this applies** — Binary trigger. Any observed state contradicting a task-brief assumption is a divergence, regardless of perceived severity. No thresholding.

    3. **Step 1: Assumption check** — Before any file modification, log `assumption_check_completed_at` and `first_modification_at` (ISO8601). Orchestrator audits ordering; out-of-order = automatic gaps_found floor.

    4. **Step 2: On divergence, STOP and write a report** — List what NOT to do (wrap up, revert, compensate, commit partial) and what to DO (stop immediately, capture work_in_progress_state, write divergence_report JSON, exit non-zero, exit 87 on report-write failure).

    5. **divergence_report schema** — Write JSON to `.planning/milestones/<phase>/divergence-reports/<task_id>-<timestamp>.json`. Enumerate every mandatory field:
       - `task_id`
       - `agent`
       - `timestamp`
       - `protocol_version`
       - `expected`
       - `found` (concrete observation, not interpretation — no "seems", "looks like", "probably")
       - `divergence_type` enum: `stale_prerequisite | unexpected_file_state | scope_overflow | manifest_violation | other`
       - `reconciliation_options` — array of concrete options A-D, each naming a specific action
       - `executor_recommendation` — pick one of your own options, 1-3 sentence rationale
       - `rationalization_check` — **MANDATORY**. Must be either the exact string `"I considered just fixing it because <reason>. I am not doing that because <protocol line>."` (with the reason/protocol placeholders filled in) OR `"N/A — no temptation present."` — omission, empty string, or null is an automatic gaps_found floor
       - `work_in_progress_state` — see sub-schema; required key even for pre-execution divergences (use `{"mid_execution": false}`)

    6. **work_in_progress_state sub-schema** — Required fields (never omit, use empty values):
       - `files_modified_so_far` (array of paths)
       - `files_created_so_far` (array of paths)
       - `uncommitted_changes` (boolean)
       - `last_completed_step` (string — last PLAN.md action finished)
       - `next_planned_step` (string — next PLAN.md action)
       End with "NO cleanup, NO revert, NO wrap up."

    7. **Orchestrator decision tree (exactly 4 options — no 5th)**:
       1. **re-route** — dispatch to different agent with same brief
       2. **re-plan** — send back to gsd-planner for delta plan; current task abandoned; new task with corrected assumptions
       3. **expand scope** — authorize updated `files_expected:` block on current task; only legitimate way to widen a manifest mid-wave; appended to `orchestrator_response`
       4. **halt phase** — stop wave entirely; escalate to human review

       Include the exact sentence: There is NO 5th option — the string `ignore and proceed` is explicitly forbidden as a decision. (Phrase this WITHOUT literally using the quoted forbidden token — e.g., "There is no 5th option. The orchestrator is forbidden from picking any variant of proceed-without-action. If tempted, it files its own divergence report and halts.")

       Show `orchestrator_response` JSON example with `decision`, `decided_at`, `decided_by`, `notes`.

    8. **Exit code 87 fallback** — If report-write fails, exit **87** (use the exact digits 87) and write structured stderr:
       ```
       DIVERGENCE_REPORT_WRITE_FAILED
       task_id: <id>
       agent: <agent>
       reason: <filesystem error message>
       fallback_payload: <the JSON you tried to write, on a single line>
       ```
       Orchestrator treats exit 87 as "divergence detected AND logged" — a successful report + side task to repair the write channel.

    9. **Multi-task simultaneous divergence** — Each task writes independently. Orchestrator processes in task-ID lexicographic order. Wave HALTS on: any `manifest_violation`, any `halt phase` decision, or 3+ divergence reports in a single wave (configurable threshold).

    10. **Validator variant** — Same schema + extra `divergence_type` value `verdict_ambiguity`. Constrained reconciliation_options for `verdict_ambiguity` (these three only): `"treat as gaps_found"`, `"treat as fail"`, `"request human disambiguation"`. Validator NEVER picks "fix it" — that is a re-plan task for the planner.

    11. **Validator pre-gate scan** — Before evaluating any of its 5 quality gates, the validator scans `.planning/milestones/<phase>/divergence-reports/` and lists every report lacking an `orchestrator_response`. Each unresolved report = automatic `gaps_found` floor. NOT advisory.

    12. **No retroactive reports** — Heading must contain the literal string `No retroactive reports`. Body: divergence report MUST be written before task exits. Post-hoc surface (git history, manifest violation, gap analysis) that was NOT reported = phase verdict `fail`. Silent absorption is never recoverable.

    13. **Audit log ownership** — Orchestrator (not executor) writes the audit-log entry referencing the report. Trust separation.

    14. **Auto-escalation separation** — Divergences are a third category, not failures. Do NOT count toward 3-consecutive-failure rule. Track `divergence_rate_per_phase` as a separate signal.

    Closing line: `Protocol version: 1.0.0`.
