# Plan 13.1-05 — HARDEN-05 Synthetic Divergence Test

## Goal

Ship the two test files that verify HARDEN-01 through HARDEN-04 actually work
end-to-end. One deterministic CJS unit test for the manifest-check utility
(HARDEN-01) and one behavioral integration test that spawns a real LLM
executor via the Task tool against the actual agent .md files, asserting on
filesystem effects (not LLM prose).

The behavioral test runs 3 scenarios × 5 runs = 15 invocations. The Phase 13
incident replay test is named EXACTLY
`test('Phase 13 incident replay: silent re-implementation is now caught')` and
is the symbolic acceptance criterion for the entire phase.

## Scope

- Wave 0 infrastructure (internal to this plan):
  - `scripts/run-behavioral-tests.cjs` runner.
  - `package.json` gains `"test:behavioral": "node scripts/run-behavioral-tests.cjs"`.
- `tests/13.1-manifest-check.test.cjs` — deterministic unit test covering
  `manifestCheck()`, `GLOBAL_ALLOWLIST`, `ORCHESTRATOR_OWNED`, `writeGapsReport()`.
- `tests/13.1-divergence-protocol.integration.test.cjs` — behavioral test:
  real LLM via Task tool, no mocking, assertions on filesystem effects
  (files modified, commits made, divergence report exists, schema-valid JSON).
- Programmatic fixture functions: `createStalePrerequisiteScenario()`,
  `createUnexpectedFileStateScenario()`, `createManifestViolationScenario()` —
  no static fixtures.
- 3 scenarios × 5 runs = 15 invocations per full behavioral run.
- Phase 13 incident replay test named EXACTLY
  `test('Phase 13 incident replay: silent re-implementation is now caught')`.
- Preserved temp directory on failure with transcript.
- CI integration: `.github/workflows/behavioral-tests.yml` auto-triggers
  `npm run test:behavioral` on PRs modifying `agents/**/*.md`,
  `get-shit-done/workflows/execute-phase.md`, or
  `get-shit-done/references/divergence-protocol.md`.

    4. **PRESERVE-ON-FAILURE PATTERN (LOAD-BEARING)** — The cleanup discipline is NON-NEGOTIABLE. Every scenario and the Phase 13 replay use the SAME shape shown above: `ctx.cleanup()` runs ONLY on the success path, inside the `try` block, AFTER all assertions pass. The `catch` branch preserves the temp dir, logs its path, and RETHROWS — it never calls cleanup. Failure diagnostics depend on the preserved directory surviving for post-mortem inspection (see HARDEN-05 decision in CONTEXT.md: "Preserved temp directory on failure. Output: scenario name, assertion name, agent transcript.").

       **Anti-patterns — FORBIDDEN. Do NOT use any of these:**
       - `afterEach(() => fs.rmSync(ctx.tempDir))` — runs on every test regardless of outcome; destroys the preserved artifact.
       - `afterEach(cleanup)` — same problem, alias form.
       - `beforeEach`/`afterEach` cleanup hooks of any kind. This test file has ZERO `afterEach` and ZERO `beforeEach` registrations.
       - `finally { ctx.cleanup() }` — runs on both success AND failure; destroys the preserved artifact on failure.
       - Unconditional cleanup after the `try/catch` block.
       - Cleanup registered via `process.on('exit')`, `t.after()`, or any other hook that fires independent of outcome.

       **Required pattern — USE THIS SHAPE ONLY:**
       ```
       try {
         // ... setup + invoke + assertions ...
         ctx.cleanup();  // preserve on failure — cleanup ONLY on success path
       } catch (err) {
         // preserve on failure — NO cleanup, log path, rethrow
         console.error(`Temp dir preserved: ${ctx.tempDir}`);
         throw err;
       }
       ```

       Every scenario block MUST contain an inline comment `// preserve on failure` on or adjacent to the success-path `cleanup()` call, so the pattern is grep-verifiable. This comment is load-bearing — checker and CI assertions count it.

## Risks

1. **LLM non-determinism** — The behavioral test assumes the executor will
   consistently file a divergence report across 15 runs. Per CONTEXT.md,
   "behavioral test flakiness is signal, not noise" — a flake = regression,
   not a test bug. If a run fails, the preserved temp dir + transcript must be
   sufficient to root-cause. Do NOT add retry logic.

2. **Task tool availability from CJS** — Node CJS tests cannot directly invoke
   Anthropic's Task tool; the harness must shell out to the `claude` CLI or
   equivalent. If neither is available in the test environment, raise a
   divergence report rather than mocking (mocking defeats the purpose per
   CONTEXT.md).

3. **CI secret availability** — `ANTHROPIC_API_KEY` must be configured as a
   repo secret. If absent in a fork PR, the behavioral job will fail. This is
   acceptable — fork PRs cannot run behavioral tests per LLM invocation cost
   and security. Document in the workflow comments if helpful.

4. **Temp dir cleanup on preserved failures** — failures leave temp dirs at
   `/tmp/gsd-13.1-*`. The CI artifact upload step captures these for 7 days.
   Local runs accumulate — add a `rm -rf /tmp/gsd-13.1-*` note to
   `scripts/run-behavioral-tests.cjs` header comment for manual cleanup
   discipline.

5. **`invokeExecutor` helper is load-bearing but undefined** — the helper
   shape depends on the project's current LLM invocation path (shell out to
   `claude` CLI, direct SDK call, or the amauta daemon). The executor of this
   task must read the current project patterns for running agents headlessly
   and pick the correct path. If no current pattern exists, file a divergence
   report — do NOT invent a new invocation pathway.
