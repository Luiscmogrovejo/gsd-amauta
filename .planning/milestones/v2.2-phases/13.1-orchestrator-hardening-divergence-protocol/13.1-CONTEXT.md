## Implementation Decisions

### HARDEN-01: Manifest Enforcement

**Schema:** Per-task `files_expected:` in PLAN.md, structured YAML with `modify:`, `create:`, `delete:[]`. All three fields mandatory. create vs modify is load-bearing (catches create-but-already-exists — the Phase 13 fingerprint). Flat lists rejected.

**Path format:** Globs for directories (`tests/13.1-*.test.cjs`), explicit paths for cross-cutting files (`agents/gsd-validator.md`). Overly broad globs (`**/*.md`) are invalid.

**Renames:** Detected via `git diff --name-status`. Rename = `delete:` (old path) + `create:` (new path). Both must be declared.

**Global allowlist:** Orchestrator-level allowlist for generated files: `package-lock.json`, `.planning/STATE.md`, coverage outputs. Not per-task. Reviewed on change.

**Orchestrator-owned files:** `.planning/STATE.md`, `.planning/ROADMAP.md`, `.planning/REQUIREMENTS.md` — executor touching any of these = hard halt regardless of manifest. These are orchestrator-only.

**Binary files:** Same rules, no carve-outs. File type irrelevant.

**Check implementation:** `gsd-tools.cjs` utility function, called from `execute-phase.md`. Testable in isolation (HARDEN-05 needs it). Workflows orchestrate, not implement.

**Check timing:** After each task completes (per-task, not per-wave). `git rev-parse HEAD` captured before and after each task. Wave-level check is a sanity wrapper.

**Multi-task waves:** Union of per-task manifests for the wave. Per-task attribution preserved in violation report for diagnosability.

**Halt behavior:** Hard halt, no exceptions. No `--force-manifest-skip` flag. If manifest misses, update manifest and re-run. Interlock with HARDEN-02: executor that needs an undeclared file hits the divergence protocol (STOP -> divergence_report -> divergence_detected -> wait).

**Violation output:** Structured JSON at `.planning/milestones/<phase>/manifest-violation-<timestamp>.json`. Fields: phase, wave, task_id, expected (modify/create/delete), actual (modified/created/deleted), violations (unexpected_modifies/creates/deletes + missing_creates), git_sha_before, git_sha_after, timestamp. Validator reads these files. HARDEN-05 asserts against them.

**Rollback override:** Single env var `GSD_MANIFEST_CHECK=warn` downgrades halts to warnings. Default = halt. Logged in violation report's `orchestrator_action` field. Removed in v2.7. No other overrides.

**Migration cutoff:** Phase 13.1+ mandatory. Phases 9-13 grandfathered. Documented in STATE.md. Orchestrator skips check for phases without `files_expected:`.

**gitignore:** Orchestrator auto-adds `-f` for `.planning/` files in `files_expected:`. Executors never use `git add -f`.

### HARDEN-02: Divergence Protocol (Decision Tree)

**Agents scoped:** All 4 executors + gsd-validator only. Not checker (read-only, different failure mode). Not universal (prompt budget, dilution, wrong mental model).

**Reference file:** `get-shit-done/references/divergence-protocol.md`. Runtime Read pattern (same as qa-checklist.md, creative-research.md). Versioned: `version: "1.0.0"` at top.

**Divergence definition:** Binary. Any observed state contradicting a task-brief assumption = divergence, regardless of perceived severity. No thresholding. False-positive volume addressed by improving PLAN.md assumptions, not by weakening the protocol.

**Assumption check first:** Before any file modification. Explicit workflow step with log line. Fields: `assumption_check_completed_at`, `first_modification_at`. Orchestrator audits ordering.

**Mid-execution divergence:** Same protocol + mandatory `work_in_progress_state` field (files_modified_so_far, files_created_so_far, uncommitted_changes, last_completed_step, next_planned_step). No cleanup, no revert, no "wrap up." Stop and report.

**divergence_report schema:** Structured JSON. Mandatory fields:
- `task_id`, `agent`, `timestamp`
- `expected` (from PLAN.md)
- `found` (concrete observation, not interpretation)
- `divergence_type` enum: `stale_prerequisite | unexpected_file_state | scope_overflow | manifest_violation | other`
- `reconciliation_options[]` (concrete options A-D)
- `executor_recommendation`
- `rationalization_check` (MANDATORY — "I considered just fixing it because [reason]. I am not doing that because [protocol]." or "N/A — no temptation present." Omission is never valid.)
- `protocol_version`

**Report location:** `.planning/milestones/<phase>/divergence-reports/<task_id>-<timestamp>.json`

**Report write failure:** Exit code 87 + structured stderr fallback. Orchestrator treats 87 = successful report + side task for write failure.

**Orchestrator response:** Decision tree, exactly 4 options: re-route, re-plan, expand scope (authorize updated `files_expected:`), halt phase. No "ignore and proceed." Decision recorded in `orchestrator_response` appended to report.

**Multi-task simultaneous divergence:** Independent reports, processed in task-ID order. Wave halts on: `manifest_violation`, any "halt phase" decision, or 3+ divergences in a wave (configurable threshold).

**Validator variant:** Same structure. Extra `divergence_type`: `verdict_ambiguity`. Constrained reconciliation: "treat as gaps_found" / "treat as fail" / "request human disambiguation." Never "fix it."

**No retroactive reports:** Must be written before task exits. Unsurfaced divergence caught by validator post-hoc = phase verdict `fail`.

**Validator reads reports:** Before evaluating gates, scans `divergence-reports/` directory. Unresolved report = automatic `gaps_found` floor. Not advisory.

**Auto-escalation:** Divergences are a third category (not failures). Don't count toward 3-consecutive-failure rule. Track `divergence_rate_per_phase` separately.

**Audit log:** Orchestrator (not executor) writes audit entry referencing report file. Trust separation.

### HARDEN-04: Validator Severity Model

**CLI shape:** `--pass` (exit 0), `--fail` (exit 1), `--gaps-found` (exit 2). Three named flags enforce vocabulary at CLI parser level. No JSON extensibility. No severity sub-fields.

**Orchestrator routing:**
- `pass` (exit 0): phase advances, roadmap updated
- `gaps_found` (exit 2): phase does NOT advance. Gaps report written. Orchestrator reroutes to re-planning (delta plan). Mini-wave + re-validation. No retry counter.
- `fail` (exit 1): phase does NOT advance. Fatal. Roadmapper invoked. Human escalation. No auto-retry.

**Gaps report:** JSON at `.planning/milestones/<phase>/gaps-report-<timestamp>.json`. Every gap tied to a `requirement_id`. `non_gaps_observations` array as pressure-release valve for genuinely cosmetic findings. No severity tagging within the gaps array.

**Untracked requirements:** Validator never invents requirement IDs. Finding without req ID = fail or non_gaps_observations. "Should be a requirement" = divergence protocol.

**Gate interaction:** 5 gates are pre-conditions, not the verdict. Recoverable gate failure ("fix without redesign") = `gaps_found`. Non-recoverable = `fail`. Validator's only judgment call.

**Migration:** Backward compatible. `--pass`/`--fail` unchanged. `--gaps-found` additive. No deprecation in 13.1.

**Auto-escalation:** `gaps_found` does NOT count as failure. Track `gaps_rate_per_phase` separately. `fail` counts — 3 consecutive = human escalation.

### HARDEN-05: Synthetic Divergence Test

**Two test files:**
- `tests/13.1-manifest-check.test.cjs` — Deterministic CJS unit test of manifest check utility. Runs in `npm test`.
- `tests/13.1-divergence-protocol.integration.test.cjs` — Behavioral integration test. Runs in `npm run test:behavioral`.

**Behavioral test uses real LLM:** Spawns real executor via Task tool against actual agent .md. No mocking. Asserts on filesystem effects (files modified, commits made, divergence report exists, schema-valid JSON), not LLM prose.

**Programmatic fixtures:** `createStalePrerequisiteScenario()` setup functions. No static fixtures.

**Three scenarios:** `stale_prerequisite`, `unexpected_file_state`, `manifest_violation`. Minimum to prove protocol generalizes.

**Failure diagnostics:** Preserved temp directory on failure. Output: scenario name, assertion name, agent transcript.

**CI integration:** `npm run test:behavioral` auto-triggered on PRs modifying `agents/**/*.md`, `get-shit-done/workflows/execute-phase.md`, or `get-shit-done/references/divergence-protocol.md`.

**Success criteria:**
1. Deterministic manifest test passes 1/1
2. Behavioral integration test passes 5/5 runs x 3 scenarios = 15 invocations
3. Phase 13 incident replay test passes — named: `test('Phase 13 incident replay: silent re-implementation is now caught')`

<specifics>
## Specific Ideas

- The `rationalization_check` field in divergence reports is the most important field in the schema — it forces agents to name the temptation they resisted, making the Phase 13 "it was faster to just fix it" pattern visible
- `non_gaps_observations` in gaps reports is a deliberate pressure-release valve — gives cosmetic findings a clean home outside the verdict, removing the host for the "cosmetic" rationalization
- The Phase 13 incident replay test (`test('Phase 13 incident replay: silent re-implementation is now caught')`) is the symbolic acceptance criterion for the entire phase
- Behavioral test flakiness is signal, not noise — if the protocol doesn't fire reliably, that's a regression, not a test problem
- HARDEN-01 and HARDEN-02 are one mechanism with two halves: the manifest check halts the wave (deterministic), the divergence protocol tells the executor what to do instead (behavioral)

</specifics>
