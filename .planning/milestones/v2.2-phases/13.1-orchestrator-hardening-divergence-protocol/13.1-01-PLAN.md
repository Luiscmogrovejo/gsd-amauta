# Plan 13.1-01 — HARDEN-01 Manifest Enforcement

## Goal

Introduce a deterministic manifest-check utility that halts the wave whenever an
executor touches files outside the declared `files_expected:` block of a task.
This is the "seatbelt" half of the mechanism; HARDEN-02 supplies the behavioral
half (what the executor does on a halt).

## Scope

- New `manifest-check` subcommand in `get-shit-done/bin/gsd-tools.cjs` (pattern:
  follow existing `commit` subcommand at ~line 150).
- Integration into `get-shit-done/workflows/execute-phase.md` as a per-task
  check, inserted near the post-wave spot-checks at lines 304-308, running
  against `git rev-parse HEAD` before/after each task.
- Global allowlist for orchestrator-generated files (`package-lock.json`,
  `.planning/STATE.md`, coverage outputs).
- JSON violation reports at
  `.planning/milestones/<phase>/manifest-violation-<timestamp>.json` with the
  full schema from CONTEXT.md.
- `GSD_MANIFEST_CHECK=warn` env var bootstrap override (downgrades halt to
  warning, logged in `orchestrator_action` field of the violation report,
  removed in v2.7).
- Orchestrator auto `git add -f` for `.planning/` files declared in
  `files_expected:` (executors never use `-f`).
- Hard halt on executor writes to orchestrator-owned files (`.planning/STATE.md`,
  `.planning/ROADMAP.md`, `.planning/REQUIREMENTS.md`) regardless of manifest.
- STATE.md documentation of the 13.1+ mandatory cutoff (phases 9-13
  grandfathered).
- HARDEN-01 entry added to `.planning/REQUIREMENTS.md` under a new Phase 13.1
  section.

## Must-Haves

- [ ] `gsd-tools.cjs manifest-check` subcommand callable from CLI and importable
      from `require()` behind a `require.main !== module` guard.
- [ ] Violation JSON schema matches CONTEXT.md exactly (10 mandatory fields).
- [ ] `execute-phase.md` invokes `manifest-check` after each task, with
      `git rev-parse HEAD` captured before and after the task.
- [ ] Global allowlist implemented and tested against at least the 3 documented
      entries.
- [ ] `GSD_MANIFEST_CHECK=warn` env override produces a warning but continues
      the wave; the downgrade is logged in `orchestrator_action`.
- [ ] Orchestrator-owned files trigger a hard halt with `orchestrator_action:
      "halt_orchestrator_owned"`.
- [ ] STATE.md carries the migration cutoff note.
- [ ] HARDEN-01 requirement added to REQUIREMENTS.md.

    Add a `manifestCheck` subcommand to `get-shit-done/bin/gsd-tools.cjs`, mirroring the structure of the existing `commit` subcommand at ~line 150. The function signature is:

    ```
    async function manifestCheck({ phase, wave, taskId, filesExpected, gitShaBefore, gitShaAfter, envOverride })
    ```

    It MUST:
    1. Compute the actual diff between `gitShaBefore` and `gitShaAfter` via `git diff --name-status <before> <after>`. Classify each path into `modified`, `created`, or `deleted`.
    2. Expand globs in `filesExpected.modify` / `.create` / `.delete` using minimatch-style matching against the actual paths. Reject manifests containing overly broad globs (`**/*.md`, `**/*`, `*`) with an error message.
    3. Compare actual vs expected and compute `violations = { unexpected_modifies: [], unexpected_creates: [], unexpected_deletes: [], missing_creates: [] }`.
    4. Consult the GLOBAL_ALLOWLIST constant (declared at top of the file, exported for tests): `['package-lock.json', '.planning/STATE.md', 'coverage/**']`. Paths matching the allowlist are removed from `unexpected_*` arrays.
    5. Consult the ORCHESTRATOR_OWNED constant: `['.planning/STATE.md', '.planning/ROADMAP.md', '.planning/REQUIREMENTS.md']`. Any match in the `actual.modified` or `actual.created` arrays produces an immediate hard halt with `orchestrator_action: 'halt_orchestrator_owned'`, regardless of `envOverride`.
    6. If any `violations.*` array is non-empty and no orchestrator-owned hit was found, write a JSON report to `.planning/milestones/<phase>/manifest-violation-<ISO8601-no-colons>.json` with exactly these fields: `phase, wave, task_id, expected {modify, create, delete}, actual {modified, created, deleted}, violations {unexpected_modifies, unexpected_creates, unexpected_deletes, missing_creates}, git_sha_before, git_sha_after, timestamp, orchestrator_action`.
    7. `orchestrator_action` is `'halt'` when `envOverride !== 'warn'`, or `'warn'` when `process.env.GSD_MANIFEST_CHECK === 'warn'`.
    8. Return `{ ok: boolean, reportPath: string|null, action: 'halt'|'warn'|'pass'|'halt_orchestrator_owned' }`. Exit code from the CLI entrypoint: 0 on `pass`/`warn`, 1 on `halt`/`halt_orchestrator_owned`.
    9. Export via `module.exports = { manifestCheck, GLOBAL_ALLOWLIST, ORCHESTRATOR_OWNED, ... }` behind a `require.main !== module` guard so tests can import it; if `require.main === module`, continue to CLI dispatch via the existing switch in `main()`.

    CLI shape:
    ```
    node get-shit-done/bin/gsd-tools.cjs manifest-check \
      --phase 13.1 --wave 1 --task-id 13.1-01-01 \
      --files-expected <path-to-yaml> \
      --before <sha> --after <sha>
    ```

    Parse `--files-expected` as a YAML file path containing the three keys. If any of `modify:`, `create:`, `delete:` is missing (not just empty), exit 1 with error `manifest-check: files_expected must declare all of modify, create, delete (use [] for empty)`.
  </action>

Use this exact markdown block (adjust surrounding markdown headings to fit the file's existing style):

    ```
    #### Per-task manifest check (HARDEN-01)

    For each task in the wave:

    1. **Before dispatching the executor**, capture the baseline sha:
       ```
       GIT_SHA_BEFORE=$(git rev-parse HEAD)
       ```
    2. **After the executor returns**, capture the post sha:
       ```
       GIT_SHA_AFTER=$(git rev-parse HEAD)
       ```
    3. **For orchestrator-owned `.planning/` files declared in `files_expected:`**, the orchestrator (not the executor) runs `git add -f <path>` before commit. Executors are FORBIDDEN from using `git add -f`.
    4. **Run the manifest check**:
       ```
       node get-shit-done/bin/gsd-tools.cjs manifest-check \
         --phase <phase> --wave <wave> --task-id <task_id> \
         --files-expected <path-to-task-manifest-yaml> \
         --before "$GIT_SHA_BEFORE" --after "$GIT_SHA_AFTER"
       ```
    5. **Exit handling**:
       - Exit 0 → task passed manifest check, proceed.
       - Exit 1 with `orchestrator_action: "halt"` → HARD HALT the wave. Read the violation report and surface it. Do not continue to the next task.
       - Exit 1 with `orchestrator_action: "halt_orchestrator_owned"` → HARD HALT always. This override ignores `GSD_MANIFEST_CHECK=warn`.
       - `GSD_MANIFEST_CHECK=warn` → exit 0, but the violation report is still written with `orchestrator_action: "warn"`. Log the warning inline. This override is removed in v2.7.

    #### Migration note

    Manifest check is MANDATORY for phases 13.1 and later. Phases 9-13 are grandfathered; the orchestrator skips the check if the PLAN.md lacks a `files_expected:` block. See `.planning/STATE.md` for the migration cutoff note.
    ```

    Do NOT remove or renumber the existing post-wave spot-checks at 304-308 — append the per-task check before them.
  </action>
