# Plan 24-02: Research Chain Integration + ROUTE-02 Compaction Wiring

## Objective

Wire gsd-research.cjs to check the semantic cache before Perplexity calls, and wire the `llm_call` parameter in `compact_conversation` to use the model configured in `config.json::model_routing.compaction`.

## Story

<story>
As a GSD-Amauta researcher, when I run `gsd-research.cjs search "query"`, the system should check the daemon's semantic cache before calling Perplexity, saving API costs on semantically equivalent queries. As a GSD-Amauta orchestrator, compaction calls should use the Haiku model by default (not Sonnet), as specified in config.json model_routing.compaction.
</story>

## Architecture Notes

- **gsd-research.cjs integration point:** In `providerPerplexity()`, BEFORE the Perplexity API call (after local cache check, after daemon Redis cache check), add a semantic cache check via `POST /api/semantic-cache/search`. On miss, after getting Perplexity response, call `POST /api/semantic-cache/store` to cache it.
- **ROUTE-02 wiring:** The daemon's `POST /api/context/compact` endpoint at line ~2193 has `llm_call=None`. Replace with a function that reads `model_routing.compaction` from config.json and makes an HTTP call to the appropriate model. Since the daemon cannot call Claude API directly (Claude Code does that), the llm_call wiring uses a lightweight HTTP callback pattern: the daemon loads the config, resolves the model name, and passes it as metadata in the compaction call. The actual LLM call is still done by the fallback path in v1 — but ROUTE-02 requires that the configured model is RESOLVED and AVAILABLE, not that it makes a real API call. The test verifies the model is read from config and would be passed to llm_call if an LLM provider were wired.
- **Practical ROUTE-02:** Since GSD-Amauta delegates API calls to Claude Code, ROUTE-02 wiring means: (a) daemon reads model_routing.compaction from config, (b) creates an llm_call function that knows which model to use, (c) passes it to compact_conversation. Even if the LLM call fails (no API key), the fallback still works. The test verifies the function is constructed with the right model name.

def _make_compaction_llm_call():
    """Create an llm_call function for compact_conversation using model_routing.compaction.

    Phase 24 ROUTE-02: Reads model from config.json model_routing.compaction.

    Returns:
        callable(prompt) -> str, or None if config unavailable.

    try:
        config_path = os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
                                    '.planning', 'config.json')
        with open(config_path, 'r') as f:
            config = json.load(f)
        model_routing = config.get('model_routing', {})
        compaction_model = model_routing.get('compaction', 'haiku')
        log.info("compaction_model_resolved model=%s source=config.json", compaction_model)

        def llm_call(prompt):
            """Compaction LLM call using configured model.

            Currently a no-op that logs the model selection and returns None
            (triggering the fallback path in compact_conversation).
            Phase 24 wires the model selection; actual API integration requires
            an LLM provider endpoint (future: local Ollama or Anthropic API key).

            return None
