# Phase 38: Blackboard Communication - Context

**Gathered:** 2026-04-14
**Status:** Ready for planning

<domain>
## Phase Boundary

Upgrade inter-agent communication from hub-spoke to blackboard architecture. Two PG tables (`agent_findings`, `agent_messages`) enable agents to share findings and ask questions. Operator supervision gates message types. Structured handoff JSON replaces ad-hoc context passing. Conflict resolution rules prevent deadlock. New daemon API endpoints expose the blackboard. All 17 agents get inter-agent communication behavioral rules.

This is infrastructure + behavioral rules across the entire agent ecosystem — not a single agent creation phase.

</domain>

<decisions>
## Implementation Decisions

### Table Schema and Migrations (COMM-01, COMM-02)
- Migrations are HAND-AUTHORED (not generated by gsd-executor-data). Core infrastructure needs exact control.

- **Migration 014-agent-findings.sql:**
  ```sql
  CREATE TABLE agent_findings (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    agent_name VARCHAR(64) NOT NULL,
    task_id VARCHAR(128) NOT NULL,
    finding_type VARCHAR(32) NOT NULL, -- 'observation', 'decision', 'warning', 'blocker'
    content TEXT NOT NULL,
    confidence REAL DEFAULT 0.8,
    created_at TIMESTAMPTZ DEFAULT NOW()
  );
  CREATE INDEX idx_findings_task ON agent_findings(task_id);
  ```

- **Migration 015-agent-messages.sql:**
  ```sql
  CREATE TABLE agent_messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    from_agent VARCHAR(64) NOT NULL,
    to_agent VARCHAR(64) NOT NULL,
    task_id VARCHAR(128) NOT NULL,
    message_type VARCHAR(32) NOT NULL, -- 'ASK_QUESTION', 'SHARE_FINDING', 'REQUEST_REVIEW', 'DELEGATE_SUBTASK'
    content TEXT NOT NULL,
    response TEXT,
    status VARCHAR(16) DEFAULT 'pending', -- 'pending', 'approved', 'denied', 'responded'
    operator_approved BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    responded_at TIMESTAMPTZ
  );
  CREATE INDEX idx_messages_task ON agent_messages(task_id);
  CREATE INDEX idx_messages_to ON agent_messages(to_agent, status);
  ```

- NO pgvector embedding column on agent_findings — findings are queried by task_id, not semantic search. Semantic search is v3.1 scope.
- Pact contracts from Phase 33: YES, add 2 new Pact contracts for findings and messages CRUD.

### Operator Supervision Model (COMM-03)
- Supervision is a BEHAVIORAL RULE in `gsd-operator.md`, not a new service
- Operator's behavioral rules updated to include approval logic:
  - `SHARE_FINDING` → auto-approved (low risk, informational)
  - `REQUEST_REVIEW` → auto-approved (reviewer makes own judgment)
  - `ASK_QUESTION` → operator reviews and approves/denies
  - `DELEGATE_SUBTASK` → operator reviews and approves/denies
- NO CLI prompt, no queue, no webhook — operator reads pending messages from PG during normal orchestration loop
- Approval latency: zero additional — happens during operator's normal task management cycle

### Handoff JSON and Token Budget (COMM-04)
- Produced by a UTILITY FUNCTION: `services/handoff.cjs` (new file, ~100 lines)
- Schema:
  ```json
  {
    "task_id": "string",
    "from_agent": "string",
    "handoff_type": "phase_complete | subtask_complete | escalation",
    "summary": "string (<=200 chars)",
    "key_findings": ["string[] (<=5 items, <=100 chars each)"],
    "decisions_made": ["string[] (<=3 items)"],
    "open_questions": ["string[] (<=3 items)"],
    "artifacts": ["string[] (file paths)"],
    "confidence": "float (0.0-1.0)",
    "full_context_ref": "string (PG record ID for full retrieval)"
  }
  ```
- Token budget enforced by the SENDER via the utility function
- Truncation: if findings exceed budget, keep 5 highest-confidence findings, store rest in PG (referenced by `full_context_ref`)
- 800-token limit is soft target — utility measures actual count and truncates until it fits

### Conflict Resolution Rules (COMM-05)
- Rules live in NEW shared file: `agents/shared/conflict-resolution.md` (same pattern as `security-rules.md` and `engineering-standards.md`)
- Included by copy in `gsd-operator.md` and `gsd-checker.md` (the two adjudicators)
- Rules:
  1. Security/safety concern raised by any agent → checker ALWAYS wins. Non-negotiable.
  2. Code correctness dispute → test results authoritative. Tests pass = executor wins. Tests fail = checker wins.
  3. Style/approach disagreement → executor gets deference unless checker identifies clear anti-pattern (god class, circular dependency).
  4. Ambiguous = neither agent can provide test evidence or concrete rule violation → escalate to operator with BOTH perspectives and confidence scores. Operator presents to user if confidence delta < 0.2.
- "Ambiguous" defined as: no test can prove either side right AND no detection rule triggered. Absence of evidence, not presence of disagreement.

### Daemon API Endpoints (New)
Six new routes in `amauta-daemon.py`:
- `POST /api/findings` — write a finding
- `GET /api/findings/:task_id` — get findings for a task
- `POST /api/messages` — send a message
- `GET /api/messages/:agent_name` — get pending messages for an agent
- `PATCH /api/messages/:id` — update status (approve/deny/respond)
- `POST /api/handoff` — generate structured handoff JSON via utility function

### Agent Behavioral Updates (All 17 Agents)
Every agent gets a new subsection `### Inter-agent communication` in behavioral rules:
"Write findings to the blackboard via `POST /api/findings` when you discover something other agents should know. Check for pending messages via `GET /api/messages/:your_name` before starting work. Respond to questions via `PATCH /api/messages/:id`."

### Wave Structure
- Wave 1: Migrations 014 + 015 + daemon API endpoints (6 routes) + handoff utility function + conflict resolution rules file
- Wave 2: Update gsd-operator.md with supervision rules + update ALL 17 agents with inter-agent communication subsection + Pact contracts for new endpoints
- Wave 3: Integration tests (round-trip flows) + regression suite

<specifics>
## Specific Ideas

- This is the most cross-cutting phase since Phase 40 — it touches all 17 agents plus infrastructure
- The operator supervision is behavioral, not mechanical — same philosophy as the entire agent system
- Conflict resolution rules are simple and deterministic (security wins, tests win, ambiguous escalates) — no complex voting or consensus mechanism
- The handoff utility enforces the 800-token budget at the sender, not a middleware layer
- Pact contracts from Phase 33 were designed with this phase in mind — they're forward contracts
- SC-1 mentions pgvector semantic search but the design decision explicitly defers this to v3.1 — tests should verify task_id-based queries, not embedding similarity
