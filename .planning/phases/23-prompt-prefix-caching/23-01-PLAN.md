# Plan 23-01: Agent Prompt Restructuring + Prefix Stability Audit Script

## Objective

Restructure all 11 specialist agent `.md` files so that stable content (role definition, design patterns, domain expertise, protocol steps, tool paths) is positioned before a `<!-- CACHE_BREAKPOINT -->` marker, and variable content (runtime-injected enrichment, task-specific context) appears after it. Create an audit script that verifies this ordering for all agents, and a test suite that proves prefix stability.

**Architectural context:** GSD-Amauta does NOT make direct Claude API calls. Claude Code (the IDE agent) reads these `.md` files as system/agent prompts. Claude Code's internal API client handles `cache_control` annotation automatically. Our job is to ensure the file structure maximizes Claude Code's ability to cache the prefix by keeping static content first and variable content last, with no volatile expressions (timestamps, random values) anywhere in the static portion.

The `<!-- CACHE_BREAKPOINT -->` marker serves as:
1. A human-readable boundary between "always the same" and "may vary per invocation"
2. A machine-parseable anchor for the audit script to validate structure
3. Documentation for future agent prompt editors about cache-sensitivity

## Verification Criteria

1. `node scripts/audit-prefix-stability.cjs` exits 0 — all 11 agents pass
2. `grep -c 'CACHE_BREAKPOINT' agents/*.md` shows exactly 11 files, 1 match each
3. `grep -rn 'datetime.now\|time.time\|Date.now\|new Date(' agents/*.md` returns 0 matches (none in stable prefix OR variable suffix — agent prompts should never contain these)
4. `node --test tests/23-prefix-stability.test.cjs` exits 0
5. For any agent file, content above `<!-- CACHE_BREAKPOINT -->` is 100% deterministic (no template variables that expand at read time)
