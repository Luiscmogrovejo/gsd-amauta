# Plan 59-01 — FIDEL-01 + FIDEL-02: Glob Ban + Agent-Conflict Diff

## Objective

Extend two existing gates in `gsd-tools.cjs` so that (a) the plan-checker
(`_validatePlanShape`) rejects any task whose `<files_expected>` contains a
glob metacharacter with a hard error code `over_broad_files_expected`, and (b)
the `agent_assignment_conflict` rejection payload emits a concrete
declared-vs-computed-vs-filelist diff instead of a bare "Plan must be
corrected" message.

Both changes are in `gsd-tools.cjs` and must NOT touch any other surface. The
manifest glob ban applies only to task-declared `files_expected` lists (not to
the existing `MANIFEST_GLOB_BLOCKLIST` used at runtime in `manifestCheck` which
is already a separate gate — we also extend that gate below per the locked
decisions).

## Verification Criteria

1. `node get-shit-done/bin/gsd-tools.cjs plan-to-tasks` on a PLAN.md
   containing `files_expected: **/*` exits 1 and prints
   `over_broad_files_expected` in the JSON errors array.
2. `node get-shit-done/bin/gsd-tools.cjs plan-to-tasks` on a PLAN.md with a
   mismatched agent exits 1 and the JSON body includes `taskId`,
   `declaredAgent`, `computedAgent`, and `files` for each conflict.
3. `node --test tests/59-01-fidel01-glob-check.test.cjs` exits 0.
4. `node --test tests/59-01-fidel02-agent-conflict.test.cjs` exits 0.

## must_haves

- FIDEL-01 glob ban applies only to new plan validation (plan-checker Pass 0 +
  manifestCheck at registration time), NOT to historical SUMMARY/VERIFICATION
  records. Historical plans already in-flight must not retroactively fail.
- `MANIFEST_GLOB_BLOCKLIST` (runtime) is extended with `?` and `[` metachar
  prefixes at `manifestCheck` call time; `_validatePlanShape` (parse time)
  adds a new `over_broad_files_expected` error code that is checked BEFORE
  the task-count cap check.
- The `agent_assignment_conflict` rejection payload keeps backward-compatible
  fields (`error`, `divergence_type`, `message`) and adds `conflicts` array
  where each entry includes `{taskId, declaredAgent, computedAgent, files}`.
  This is already the shape at L1523-L1529 — FIDEL-02 just ensures `files` is
  present and `message` is human-actionable.
- No new npm dependencies, no new runtime, no touch to any Python file.

    **Step 1 — Define glob metacharacter set for plan-checker.**

    At the top of `_validatePlanShape` (around L1120, after the `<story>`

    ```js
    const GLOB_METACHARS = ['*', '?', '[', '{'];
    ```

    **Step 2 — Extend the per-task validation loop.**

    In the per-task field validation loop (around L1174), BEFORE the
    `missing_agent` / `missing_files_expected` / `missing_acceptance_criteria`
    checks, add a new glob-ban check that iterates
    `task.filesExpected.modify`, `task.filesExpected.create`, and
    `task.filesExpected.delete` and for each path entry checks whether any
    character in `GLOB_METACHARS` appears in the path string.

    When a glob metachar is found, push:
    ```js
    errors.push({
      code: 'over_broad_files_expected',
      taskId: task.id,
      offendingPath: entry,
      message: `Task ${task.id} files_expected contains over-broad glob "${entry}" — use concrete file paths only.`,
    });
    ```

    Push one error per offending path entry (not one per task). Do NOT stop
    iteration early — collect all offending paths.

    **Step 3 — Extend MANIFEST_GLOB_BLOCKLIST.**

    At L679 (the existing `MANIFEST_GLOB_BLOCKLIST` constant definition),
    extend the array to also include glob metacharacter prefixes that `?` and
    `[` patterns would match. Specifically, add entries for these patterns that
    defeat the purpose of a manifest at runtime:

    ```js
    const MANIFEST_GLOB_BLOCKLIST = ['**/*.md', '**/*', '*', '**/?*', '**/*[*'];
    ```

    Note: The metachar check in `_validatePlanShape` is a structural check
    (any path entry containing `*`, `?`, `[`, or `{`). The `MANIFEST_GLOB_BLOCKLIST`
    is for exact-string matching at runtime in `manifestCheck`. Both complement
    each other — the plan-checker catches at parse time; manifestCheck catches
    at runtime with the existing `MANIFEST_GLOB_BLOCKLIST.includes(entry)` check.

    **Step 4 — Ensure over_broad_files_expected does NOT suppress other errors.**

    The glob check pushes into `errors` and continues. If `errors.length > 0`
    at end of the per-task loop, the existing `return { valid: false, errors, ... }`
    path fires. No structural change to the return path is needed.

    ```js
    'use strict';
    const { test } = require('node:test');
    const assert = require('node:assert/strict');
    const path = require('path');

    // Internal: require gsd-tools.cjs for _validatePlanShape via its module.exports
    // gsd-tools exports GLOBAL_ALLOWLIST, ORCHESTRATOR_OWNED, MANIFEST_GLOB_BLOCKLIST, manifestCheck, planToTasks
    const toolsPath = path.resolve(__dirname, '../get-shit-done/bin/gsd-tools.cjs');

    // Build a minimal PLAN.md string with a glob in files_expected.
    // NOTE: XML tag names in the template literal are intentionally broken with
    // zero-width comments (/**/) so that the plan-checker's own <task> regex
    // does not pick up these test fixtures as real plan tasks when 59-01-PLAN.md
    // is itself parsed by plan-to-tasks.
    const T = 'task', S = 'story', A = 'agent', FE = 'files_expected', AC = 'acceptance_criteria';
    function buildPlan(filesExpectedYaml) {
      return [
        '---', 'plan_id: test-glob', '---',
        `<${S}><title>T</title><success_criteria>G W T</success_criteria><doc_refs></doc_refs></${S}>`,
        `<${T} id="test-glob-01">`,
        '<title>Test Task</title>',
        `<${A}>executor-backend</${A}>`,
        '<depends_on>[]</depends_on>',
        '<read_first>- some/file.js</read_first>',
        '<action>Do something.</action>',
        `<${AC}>- echo ok</${AC}>`,
        `<${FE}>`,
        filesExpectedYaml,
        `</${FE}>`,
        `</${T}>`,
      ].join('\n');
    }

    test('FIDEL-01: plan-to-tasks rejects **/* glob in files_expected', async (t) => {
      const { planToTasks } = require(toolsPath);
      const fs = require('fs');
      const os = require('os');
      const tmp = path.join(os.tmpdir(), `fidel01-test-${Date.now()}.md`);
      const content = buildPlan('modify:\n  - **/*\ncreate: []\ndelete: []');
      fs.writeFileSync(tmp, content, 'utf-8');
      try {
        const result = await planToTasks(tmp, { cwd: process.cwd() });
        assert.equal(result.error, 'validation_failed', 'should return validation_failed error');
        const globError = (result.errors || []).find(e => e.code === 'over_broad_files_expected');
        assert.ok(globError, 'should have over_broad_files_expected error');
        assert.equal(globError.taskId, 'test-glob-01', 'error should name the task id');
        assert.ok(globError.offendingPath.includes('**'), 'error should name the offending path');
      } finally {
        try { fs.unlinkSync(tmp); } catch {}
      }
    });

    test('FIDEL-01: plan-to-tasks rejects ? glob in files_expected', async (t) => {
      const { planToTasks } = require(toolsPath);
      const fs = require('fs');
      const os = require('os');
      const tmp = path.join(os.tmpdir(), `fidel01-test-q-${Date.now()}.md`);
      const content = buildPlan('modify:\n  - services/?.py\ncreate: []\ndelete: []');
      fs.writeFileSync(tmp, content, 'utf-8');
      try {
        const result = await planToTasks(tmp, { cwd: process.cwd() });
        assert.equal(result.error, 'validation_failed');
        const globError = (result.errors || []).find(e => e.code === 'over_broad_files_expected');
        assert.ok(globError, 'should reject ? metachar');
        assert.equal(globError.taskId, 'test-glob-01');
      } finally {
        try { fs.unlinkSync(tmp); } catch {}
      }
    });

    test('FIDEL-01: plan-to-tasks accepts concrete file path (no glob)', async (t) => {
      const { planToTasks } = require(toolsPath);
      const fs = require('fs');
      const os = require('os');
      const tmp = path.join(os.tmpdir(), `fidel01-test-ok-${Date.now()}.md`);
      // Use a non-conflicting agent to avoid agent_assignment_conflict masking this
      const content = buildPlan('modify:\n  - services/my_file.py\ncreate: []\ndelete: []');
      fs.writeFileSync(tmp, content, 'utf-8');
      try {
        const result = await planToTasks(tmp, { cwd: process.cwd() });
        // Should not fail with over_broad_files_expected — other errors may exist (e.g. agent conflict) but not this one
        const globErrors = (result.errors || []).filter(e => e.code === 'over_broad_files_expected');
        assert.equal(globErrors.length, 0, 'concrete path should not trigger glob ban');
      } finally {
        try { fs.unlinkSync(tmp); } catch {}
      }
    });
    ```

    **File 2: tests/59-01-fidel02-agent-conflict.test.cjs**

    Test that `agent_assignment_conflict` includes `declaredAgent`, `computedAgent`, `files`:

    ```js
    'use strict';
    const { test } = require('node:test');
    const assert = require('node:assert/strict');
    const path = require('path');
    const fs = require('fs');
    const os = require('os');

    const toolsPath = path.resolve(__dirname, '../get-shit-done/bin/gsd-tools.cjs');

    // Same pattern: break up XML tag names to avoid plan-parser picking these up
    const T = 'task', S = 'story', A = 'agent', FE = 'files_expected', AC = 'acceptance_criteria';
    function buildConflictPlan() {
      // executor-frontend routing file (*.tsx) but agent says executor-backend — guaranteed conflict
      return [
        '---', 'plan_id: test-conflict', '---',
        `<${S}><title>T</title><success_criteria>G W T</success_criteria><doc_refs></doc_refs></${S}>`,
        `<${T} id="test-conflict-01">`,
        '<title>Conflict Task</title>',
        `<${A}>executor-backend</${A}>`,
        '<depends_on>[]</depends_on>',
        '<read_first>- some/file.js</read_first>',
        '<action>Do something.</action>',
        `<${AC}>- echo ok</${AC}>`,
        `<${FE}>`,
        'modify:',
        '  - src/components/MyComponent.tsx',
        'create: []',
        'delete: []',
        `</${FE}>`,
        `</${T}>`,
      ].join('\n');
    }

    test('FIDEL-02: agent_assignment_conflict payload includes declaredAgent, computedAgent, files', async (t) => {
      const { planToTasks } = require(toolsPath);
      const tmp = path.join(os.tmpdir(), `fidel02-test-${Date.now()}.md`);
      fs.writeFileSync(tmp, buildConflictPlan(), 'utf-8');
      try {
        const result = await planToTasks(tmp, { cwd: process.cwd() });
        assert.equal(result.error, 'agent_assignment_conflict', 'should detect conflict');
        assert.ok(Array.isArray(result.conflicts), 'conflicts array required');
        assert.ok(result.conflicts.length >= 1, 'at least one conflict entry');
        const c = result.conflicts[0];
        assert.equal(c.taskId, 'test-conflict-01', 'taskId present');
        assert.ok('declaredAgent' in c, 'declaredAgent field present');
        assert.ok('computedAgent' in c, 'computedAgent field present');
        assert.ok(Array.isArray(c.files), 'files array present');
        assert.ok(c.files.length >= 1, 'files array non-empty');
        assert.ok(result.message.includes(c.taskId), 'message references task id');
        assert.ok(result.message.includes(c.declaredAgent), 'message references declared agent');
        assert.ok(result.message.includes(c.computedAgent), 'message references computed agent');
      } finally {
        try { fs.unlinkSync(tmp); } catch {}
      }
    });

    test('FIDEL-02: divergence_type is agent_assignment_conflict', async (t) => {
      const { planToTasks } = require(toolsPath);
      const tmp = path.join(os.tmpdir(), `fidel02-type-${Date.now()}.md`);
      fs.writeFileSync(tmp, buildConflictPlan(), 'utf-8');
      try {
        const result = await planToTasks(tmp, { cwd: process.cwd() });
        assert.equal(result.divergence_type, 'agent_assignment_conflict');
      } finally {
        try { fs.unlinkSync(tmp); } catch {}
      }
    });
    ```
