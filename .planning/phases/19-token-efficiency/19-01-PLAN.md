# Plan 19-01: Enrichment Dedup + Perplexity Truncation + RPETD Content Caps

## Objective

Reduce wasted tokens per task lifecycle by (1) skipping redundant Layer 2 R-phase enrichment when Layer 1 ran recently, (2) capping Perplexity output before it reaches agents, and (3) adding soft size guidance to RPETD phase writes. All three requirements are independent and non-breaking.

## Why Single Plan

TOKEN-01, TOKEN-02, and TOKEN-03 are independent changes in different files. None exceed 1 hour of executor work. Bundling avoids 3 separate plan overheads while keeping tasks isolated (each task touches different files). Total estimated effort: ~30 min.

## Context

- `amauta.py` L3368-3378: Layer 1 enrichment at claim-time -- stores note with agent="system-enrichment"
- `amauta.py` L1884-2154: `_rpetd_phase_enrich()` -- Layer 2 enrichment per RPETD phase
- `amauta.py` L1907-1951: R-phase section fires RLM + memory + SKB queries (redundant with Layer 1)
- `amauta.py` L3411-3506: `cmd_rpetd()` -- RPETD phase write handler, no size enforcement
- `amauta.py` L1240-1241: `_append_note()` stores ISO timestamp via `_now()`
- `amauta.py` L682-730: `_research_chain_query()` already truncates results to 500 chars
- `gsd-research.cjs` L250-320: `providerPerplexity()` returns raw answer (up to 4096 tokens), stores 2000 chars to memory but returns full answer
- `gsd-research.cjs` L519-528: `formatResult()` for perplexity prints full `r.text` with no truncation
- Research finding: Layer 1 + Layer 2 R-phase overlap wastes ~1,600-3,200 tokens per task when R-phase runs within 5 min of claim
- Research finding: Perplexity raw output can be 4,096 tokens; `_research_chain_query()` caps at 500 chars but `gsd-research.cjs` stdout has no cap
- Research finding: RPETD T-phase can exceed 5,000 chars (agents paste full test output); phases are read-capped at 300-400 chars in downstream enrichment, but the stored content still bloats task JSON

## Risks

1. **TOKEN-01 timestamp parsing edge case** -- Task might not have a system-enrichment note (first-time claim failed before enrichment). Mitigation: if no enrichment note found, proceed with normal enrichment (cache miss = run normally).
2. **TOKEN-01 clock skew** -- Comparison uses task note timestamps (ISO strings from `_now()`), not wall clock. Both Layer 1 and Layer 2 use the same `_now()` function, so no skew within same process.
3. **TOKEN-02 strips useful content** -- Perplexity preamble removal might strip legitimate first sentences. Mitigation: only strip common patterns ("Here is", "Based on", "I found", "Sure,", "Let me") at start of text, preserve everything after.
4. **TOKEN-03 soft cap surprises agents** -- Agents see a WARNING they did not expect. Mitigation: warning is informational (does NOT block the write), and includes guidance on optimal sizes.

       enrichment_ts = _last_enrichment_ts(item)
       if enrichment_ts:
           try:
               from datetime import datetime, timezone
               enrich_dt = datetime.fromisoformat(enrichment_ts)
               now_dt = datetime.now(timezone.utc)
               age_seconds = (now_dt - enrich_dt).total_seconds()
               if age_seconds < ENRICHMENT_DEDUP_WINDOW:

                       f"[Layer 1 cache hit -- skipping enrichment] "
                       f"Claim-time context injected {int(age_seconds)}s ago (within {ENRICHMENT_DEDUP_WINDOW}s window)"

                   if supplement_parts:
                       return "\n\n".join(supplement_parts)
                   return ""
           except Exception:
               pass  # Parse error → proceed with normal enrichment
       # (rest of existing R-phase code continues below)
   ```

   /**
    * Strip common Perplexity preamble patterns from the start of answers.
    * These boilerplate sentences waste tokens without adding value.
    */
   function stripPreamble(text) {
     if (!text) return text;
     // Strip common opening patterns (case-insensitive, match from start)
     const patterns = [
       /^(?:here\s+(?:is|are)\s+(?:a\s+)?(?:comprehensive|detailed|brief|quick)?\s*(?:overview|summary|breakdown|look|analysis|guide|explanation)[^.]*[.:]\s*)/i,
       /^(?:based\s+on\s+(?:my\s+)?(?:research|analysis|findings|the\s+(?:available\s+)?(?:information|data|sources))[^.]*[.:]\s*)/i,
       /^(?:i\s+found\s+(?:that\s+)?(?:the\s+following|several|some|a\s+few)[^.]*[.:]\s*)/i,
       /^(?:sure[,!.]?\s*(?:here\s+(?:is|are))?[^.]*[.:]\s*)/i,
       /^(?:let\s+me\s+(?:provide|explain|break\s+down|summarize)[^.]*[.:]\s*)/i,
       /^(?:certainly[,!.]?\s*)/i,
       /^(?:absolutely[,!.]?\s*)/i,
     ];
     let result = text;
     for (const pattern of patterns) {
       result = result.replace(pattern, '');
     }
     return result.trim();
   }
   ```
