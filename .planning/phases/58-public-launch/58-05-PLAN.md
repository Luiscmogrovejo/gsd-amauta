    ```markdown
    # GSD-Amauta Quickstart

    This guide takes you from zero to your first shipped feature phase in about 15 minutes.

    **Prerequisites:** Node.js >= 20, Docker, Python 3.11+, Claude Code (or any MCP-compatible agent)

    ---

    ## Step 1: Install

    ```bash
    npm install -g gsd-amauta
    ```

    Verify the install:
    ```bash
    gsd-amauta --version
    # gsd-amauta 3.3.0
    ```

    ---

    ## Step 2: Start infrastructure

    GSD-Amauta uses PostgreSQL for persistent memory and Valkey for caching. Both run in Docker.

    ```bash
    docker compose -f $(npm root -g)/gsd-amauta/docker/docker-compose.yml up -d
    ```

    Expected output:
    ```text
    [+] Running 3/3
     ✔ Network gsd-network      Created
     ✔ Container gsd-postgres   Started
     ✔ Container gsd-valkey     Started
    ```

    If you already have PostgreSQL running on port 5432, set `GSD_PG_HOST` and `GSD_PG_PORT` before continuing.

    ---

    ## Step 3: Run init

    The `init` command runs a 7-step setup: detects your IDE, installs agents and skills, runs database migrations, and starts the daemon.

    ```bash
    npx gsd-amauta init
    ```

    Expected output:
    ```text

    gsd-amauta init
    ================

    [1/7] Detecting IDEs... claude-code detected at /Users/you/.claude
    [2/7] Installing agents, commands, skills... install complete
    [3/7] Detecting infrastructure... pg-docker on 5432, valkey on 6379
    [4/7] Running migrations... 24 migrations applied
    [5/7] Starting daemon... daemon started on port 18799
    [6/7] Verifying system... health ok
    [7/7] Running assertions... 5/5 pass

    Step                     Status   Duration     Message
    ──────────────────────────────────────────────────────────────────────
    detect_ides              pass     0.1s         claude-code detected
    install_skills           pass     2.3s         install complete
    detect_infra             pass     0.2s         pg-docker on 5432
    migrations               pass     1.1s         24 migrations applied
    start_daemon             pass     0.8s         daemon started on port 18799
    verify                   pass     0.1s         health ok
    run_assertions           pass     0.2s         5/5 pass

    gsd-amauta installed (5.1s) — run `gsd-amauta doctor` to verify.
    ```

    If any step shows `fail`, run `gsd-amauta doctor` for diagnostics:
    ```bash
    gsd-amauta doctor
    ```

    Add `--verbose` to see full debug output:
    ```bash
    npx gsd-amauta init --verbose
    ```

    ---

    ## Step 4: Create a project in Claude Code

    Open your project directory in Claude Code. GSD-Amauta installs slash commands that Claude Code picks up automatically.

    Type in the Claude Code chat:
    ```
    /amauta:new-project
    ```

    GSD-Amauta will ask you a few questions about your project (name, goal, tech stack) and create `.planning/PROJECT.md` and `.planning/ROADMAP.md`.

    Alternatively, if you already have a project, use:
    ```
    /amauta:new-milestone
    ```

    ---

    ## Step 5: Plan your first phase

    The RPETD pipeline breaks every feature into phases. A phase is a unit of work plannable in one sitting and executable in one session. Let's plan Phase 1.

    In Claude Code:
    ```
    /amauta:plan-phase 1
    ```

    GSD-Amauta's planner agent will:
    1. Search your project memory for prior learnings
    2. Decompose the phase goal into tasks with acceptance criteria
    3. Write plan files to `.planning/phases/01-*/`
    4. Register tasks in the task board

    Expected output in Claude Code:
    ```text
    ## Planning Complete

    Phase: 1 — [your phase name]
    Plans created: 2
    Waves: Wave 1 (parallel) → Wave 2 (sequential)
    Tasks: 6 total

    Plans written:
    - .planning/phases/01-.../01-01-PLAN.md
    - .planning/phases/01-.../01-02-PLAN.md
    ```

    Review the plan files before executing. Each task has:
    - `<action>` — concrete instructions
    - `<acceptance_criteria>` — grep-verifiable pass conditions
    - `<files_expected>` — exact files to create or modify

    ---

    ## Step 6: Execute the phase

    Once you're satisfied with the plan:
    ```
    /amauta:execute-phase 1
    ```

    The orchestrator dispatches each task to the right specialist agent:
    - `executor-backend` — Python, Node.js, APIs, databases
    - `executor-frontend` — React, CSS, UI components
    - `executor-infra` — Docker, CI/CD, deployment scripts
    - `executor-general` — Documentation, config, agent definitions

    Agents run through 5 phases: **R**esearch → **P**lan → **E**xecute → **T**est → **D**eliver (RPETD). Each phase is gated — an agent cannot skip to Execute without completing Research and Plan first.

    If an agent finds a plan-vs-reality mismatch (a "divergence"), it surfaces it as an observation instead of silently fixing it. You decide: absorb, escalate, or replan.

    Expected outcome:
    ```text
    Phase 1 complete.
    Tasks: 6/6 pass
    Commits: 4 (feat: ..., test: ..., chore: ...)
    ```

    ---

    ## Step 7: Verify and ship

    Check the task board:
    ```bash
    amauta board
    ```

    Run the full test suite:
    ```bash
    npm test
    pytest services/
    ```

    Commit and push:
    ```bash
    git log --oneline -5    # Review commits created by the executor
    git push origin main
    ```

    That's it — your first phase is shipped. GSD-Amauta stored everything it learned (patterns, failures, validated approaches) in PostgreSQL. Future phases start smarter.
