# Plan 58-03: npm Publish Workflow with Provenance

## Objective

Create `.github/workflows/release.yml` that triggers on semver tag push (`v[0-9]+.[0-9]+.[0-9]+`), runs the full test suite (Node.js + pytest), then publishes to npm with `--provenance`. Update `package.json` to add `keywords`, update `engines` to Node >= 20, update `files` whitelist to exclude dev/planning artifacts from the published package, and bump `version` to `3.3.0`. This plan depends on 58-02 (LICENSE finalized — the `license` field in package.json must match the audited LICENSE file).

## Locked Decisions

1. Workflow file = `.github/workflows/release.yml`.
2. Trigger: `push` with `tags: ['v[0-9]+.[0-9]+.[0-9]+']` pattern.
3. Jobs: (1) checkout with `actions/checkout@v4`, (2) setup-node 20 with `npm` cache, (3) `npm ci`, (4) `npm test`, (5) `pytest services/` (if Python files exist), (6) `npm publish --provenance --access public` with `NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}`.
4. Permissions at job level: `id-token: write` (REQUIRED for OIDC provenance), `contents: read`.
5. package.json `"version"` bumped from `"2.8.0"` to `"3.3.0"`.
6. package.json `"engines"` updated from `"node": ">=18.0.0"` to `"node": ">=20.0.0"` (matches CI matrix; Node 18 EOL April 2025).
7. package.json `"keywords"` gets `"agents"`, `"development"`, `"harness"`, `"module-system"` added (current list already has claude-code, ai, multi-agent, rpetd — merge, don't replace).
8. package.json `"files"` already has most needed entries; add exclusion of `.planning/`, `data/`, `tests/` that should NOT publish. Current `files` array is an allowlist — verify it does NOT include `.planning`, `data`, or `tests` (it doesn't — they're not listed, so they're already excluded from `npm publish`).
9. Current `files` array already includes: `bin`, `commands`, `get-shit-done`, `agents`, `skills`, `hooks/dist`, `scripts`, `services`, `docker`, `migrations`, `references`. This is correct — these are the runtime files. No change needed except to add `registry` (Phase 57 marketplace index will live there).

## must_haves

- `permissions: id-token: write` is at the JOB level (not workflow level) — this is required for npm provenance OIDC. Without it, `--provenance` silently produces no attestation.
- `--access public` is present — without it, scoped packages default to private and the publish fails.
- The workflow does NOT run on push to branches (only on tags) — prevents accidental publishes on PR merges.
- The `npm test` step runs BEFORE `npm publish` — a failing test suite must block the publish.
- `pytest services/` step uses `if: hashFiles('services/requirements.txt') != ''` or similar guard so the workflow doesn't fail if pytest is not installed in the runner.

  <action>
    Create `.github/workflows/release.yml` with this exact content:

    ```yaml
    name: Release — npm publish with provenance

    on:
      push:
        tags:
          - 'v[0-9]+.[0-9]+.[0-9]+'

    concurrency:
      group: ${{ github.workflow }}-${{ github.ref }}
      cancel-in-progress: false

    jobs:
      release:
        runs-on: ubuntu-latest
        timeout-minutes: 15

        permissions:
          id-token: write   # Required for npm --provenance (OIDC token)
          contents: read

        steps:
          - uses: actions/checkout@34e114876b0b11c390a56381ad16ebd13914f8d5 # v4

          - name: Set up Node.js 20
            uses: actions/setup-node@49933ea5288caeca8642d1e84afbd3f7d6820020 # v4
            with:
              node-version: '20'
              cache: 'npm'
              registry-url: 'https://registry.npmjs.org'

          - name: Install Node.js dependencies
            run: npm ci

          - name: Run Node.js tests
            shell: bash
            run: npm test

          - name: Run coverage ratchet
            shell: bash
            run: node scripts/coverage-ratchet.cjs

          - name: Set up Python 3.11
            uses: actions/setup-python@v5
            with:
              python-version: '3.11'

          - name: Install Python dependencies
            run: |
              if [ -f services/requirements.txt ]; then
                pip install -r services/requirements.txt
              fi

          - name: Run Python tests
            run: |
              if [ -d services ] && ls services/test_*.py 1>/dev/null 2>&1; then
                python -m pytest services/ -v --tb=short
              fi

          - name: Publish to npm with provenance
            run: npm publish --provenance --access public
            env:
              NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
    ```

    Notes on this YAML:
    - `cancel-in-progress: false` — do NOT cancel a publish mid-flight if another tag push happens simultaneously.
    - pinned action SHAs match the existing test.yml pattern (same SHA for checkout and setup-node).
    - `registry-url: 'https://registry.npmjs.org'` is required for `NODE_AUTH_TOKEN` to be picked up by npm.
    - Python step guards with `if [ -f ... ]` to not fail on fresh runners without requirements.txt.
  </action>
