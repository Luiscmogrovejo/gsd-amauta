# Plan 18-01: Source Filtering + Recency Decay

## Objective

Make memory search results useful by default: exclude low-signal sources (task_event, rpetd_phase) from search unless explicitly requested, and add time-based decay so recent memories rank above stale ones.

## Why This Order

MEM-01 and MEM-03 both modify the same 4 functions: `_score_memories()` and `_score_semantic_results()` in pg_store.py, plus `memory_search()` and `memory_semantic_search()`. Bundling them avoids touching these functions twice. MEM-02 (retention) is independent infrastructure that adds a new table and daemon thread -- separate plan.

## Context

- `pg_store.py` L43-53: SOURCE_SCORES dict (lesson-learned=+4, task_event=+0)
- `pg_store.py` L233-294: `memory_search()` -- text/ILIKE search with no source exclusion
- `pg_store.py` L296-316: `_score_memories()` -- source bonus only, no time component
- `pg_store.py` L1137-1228: `memory_semantic_search()` + `_score_semantic_results()` -- same gap
- `sqlite_store.py` L316-370: `memory_search()` -- needs parity changes
- `sqlite_store.py` L372+: `_score_memories()` -- needs parity changes
- `amauta-daemon.py` L1257-1276: `/api/memory/search` endpoint -- passes body params to store
- `amauta-daemon.py` L1294-1313: `/api/memory/semantic-search` endpoint -- same pattern
- `gsd-memory.cjs` L389-440: `cmdSearch()` -- needs `--include-noise` flag
- `amauta.py` L517-601: `_mem_pg_search()` -- amauta.py's own LIKE search (separate from daemon)
- Research finding: 85% of entries were noise sources (task_event + rpetd_phase + distilled). Phase 15 purged distilled, but task_event and rpetd_phase still pollute search.
- Research finding: scoring has zero time component -- 6-month-old entry = today's entry at same similarity.
- Env var `GSD_RECENCY_DECAY_PER_30D` controls decay rate (default 0.5 points per 30 days).

## Risks

1. **Source filtering breaks callers that need task_event** -- Mitigation: explicit `--include-noise` / `include_noise=True` flag preserves access. Only default behavior changes.
2. **Recency decay penalizes valuable old learnings** -- Mitigation: lesson-learned gets +4 source bonus, max recency penalty is capped at -3 (6 months), so even oldest lesson-learned never drops below +1.
3. **SQLite store lacks TIMESTAMPTZ** -- Mitigation: SQLite stores ISO strings; parse with `datetime.fromisoformat()` which handles both.
4. **amauta.py `_mem_pg_search()` has its own SQL** -- Mitigation: apply same exclude_sources logic there (WHERE clause addition).

<task id="4" file="services/pg_store.py,services/sqlite_store.py" req="MEM-03">
<title>Add recency decay to _score_memories() and _score_semantic_results()</title>
<read_first>
- services/pg_store.py L296-316 (_score_memories)
- services/pg_store.py L1207-1228 (_score_semantic_results)
- services/sqlite_store.py L372-400 (_score_memories)
- services/pg_store.py L43-53 (SOURCE_SCORES for context)
</read_first>
<acceptance_criteria>
- Given GSD_RECENCY_DECAY_PER_30D is not set (uses default 0.5)
- Given a memory entry was created 60 days ago with source='auto_learning' and text_rank=0.5
- When _score_memories processes this entry
- Then score = (0.5 * 10) + 3 + (-1.0) = 7.0 (decay = 0.5 * 2 months = 1.0)
- Given GSD_RECENCY_DECAY_PER_30D=0 (decay disabled)
- When _score_memories processes the same entry
- Then score = (0.5 * 10) + 3 = 8.0 (no decay)
- Given an entry is 200 days old
- When _score_memories processes it
- Then decay is capped at -3.0 (max 6 months penalty), not -3.33
- Verify: `grep "recency_decay\|GSD_RECENCY_DECAY" services/pg_store.py` returns >= 3
- Verify: `grep "recency_decay\|days_old" services/sqlite_store.py` returns >= 2
</acceptance_criteria>
<action>
1. In pg_store.py, add at module level near SOURCE_SCORES:
   ```python
   RECENCY_DECAY_PER_30D = float(os.environ.get("GSD_RECENCY_DECAY_PER_30D", "0.5"))
   MAX_RECENCY_PENALTY = 3.0  # Cap at 6 months of decay
   ```
2. In `_score_memories()`:
   - Parse `created_at` from the row (already a datetime or ISO string)
   - Compute `days_old = (datetime.now(timezone.utc) - created_at).days`
   - Compute `recency_penalty = min(RECENCY_DECAY_PER_30D * (days_old / 30), MAX_RECENCY_PENALTY)`
   - New score formula: `d["score"] = round(text_rank * 10 + source_bonus - recency_penalty, 2)`
   - Handle edge case: if `created_at` is None or unparseable, skip decay (penalty = 0)
3. In `_score_semantic_results()`:
   - Same recency_penalty logic
   - New formula: `d["score"] = round(similarity * 10 + source_bonus - recency_penalty, 2)`
4. In sqlite_store.py `_score_memories()`:
   - Same logic but parse ISO string with `datetime.fromisoformat()`
   - Handle SQLite's string format: `datetime.fromisoformat(created_at_str)`
5. In amauta.py `_mem_pg_search()` (L546-564):
   - Add recency decay to the SQL CASE expression OR apply post-query in Python
   - Recommendation: apply post-query in Python for consistency with pg_store.py approach
   - After building `out` list, compute decay for each entry and subtract from score
</action>
</task>
