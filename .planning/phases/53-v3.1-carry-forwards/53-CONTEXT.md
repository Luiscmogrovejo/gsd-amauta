## Implementation Decisions

### Area 1 — POLISH-01: Skill input/output schemas

EXTEND `services/skill_schema.py` `SkillFrontmatter` (Phase 43):

```python
class SkillFrontmatter(BaseModel):
    name: str
    description: str
    category: str
    version: str
    security_class: str   # MUST appear BEFORE allowed-tools per Phase 43-03-02 contract
    allowed_tools: list[str] = Field(alias="allowed-tools")
    depends_on: list[str] = Field(default_factory=list)
    # NEW in Phase 53 POLISH-01:
    input_schema: dict | None = None      # JSON-Schema-shaped dict, optional
    output_schema: dict | None = None     # JSON-Schema-shaped dict, optional
```

Field declaration order LOCKED extension: existing 7 fields stay; `input_schema`, `output_schema` appended (positions 8 + 9). Phase 43 grep tests verify the existing 7-field order — new fields appended don't disturb it.

`gsd-tools skills validate` (Phase 43) checks: if `input_schema` is present, validate it against JSON Schema meta-schema (use a minimal pure-Python validator or `jsonschema` library if already in deps; recommend optional dep with `_HAS_JSONSCHEMA` fallback similar to `_HAS_PYDANTIC`). Same for `output_schema`. Malformed schema → validation fails with structured error pointing to the offending key.

Backward-compat: skills without `input_schema`/`output_schema` continue to validate cleanly (fields are optional). No existing skill file requires modification.

### Area 2 — POLISH-02: Installer `--upgrade` + `--uninstall`

EXTEND `bin/init.cjs` (Phase 44 — 7-step installer):

NEW flags (additive — every existing flag unchanged):
- `--upgrade` — re-runs init in upgrade mode: detects current install version, applies new migrations, preserves user data
- `--uninstall` — removes Amauta from project: deletes `.claude/`, `.cursor/`, `.opencode/` skill+agent subdirs created by Amauta, deletes generated `platform-codes.yaml` IF generated by Amauta (not user-edited — check by hash), preserves user-authored files (`.planning/`, `agents/`, `skills/`, `tests/`)

NEW step name vocabulary (extends Phase 44's existing step names):
- upgrade flow: `detect_current_version`, `compute_migration_delta`, `apply_upgrade_migrations`, `update_install_record`, `restart_daemon`, `run_assertions` — reuses the existing 7-step flow's `assertions` step
- uninstall flow: `read_install_record`, `remove_skills`, `remove_agents`, `remove_generated_config`, `clear_install_record`, `post_uninstall_verify` — mirrors Phase 49 module uninstall vocabulary

Worst-of-status combinator + frozen exit codes 0/1 (Phase 44 contract) preserved.

`buildStepResult()` (Phase 44) reused unchanged.

### Area 3 — POLISH-03: MCP `amauta/bearings` tool

EXTEND `services/amauta-mcp.py` (Phase 46) tool list:

```python
TOOLS.append(Tool(
    name="amauta/bearings",
    description="Return the deterministic bearings block (project state, recent activity, plan progress, pattern stats, recommendation) as JSON. Wraps `gsd-tools bearings`.",
    inputSchema={
        "type": "object",
        "properties": {
            "terse": {"type": "boolean", "default": False},
            "token_budget": {"type": "integer", "default": 600},
        },
    },
))
```

Handler invokes `gsd-tools bearings --json` via subprocess; passes `--terse` and `--token-budget <N>` if requested. Returns parsed JSON verbatim (schema_version "1.0" guaranteed by Phase 45 contract).

Error contract: `pg_unavailable` (Phase 45 graceful degradation surfaces in JSON; pass through), `internal_error` on subprocess failure.

### Area 4 — POLISH-04: MCP `amauta/agent-hydrate` tool

Same pattern as POLISH-03 but wraps `gsd-tools agent-hydrate`:

```python
TOOLS.append(Tool(
    name="amauta/agent-hydrate",
    description="Return the agent-specific hydration block (memory, blackboard, valkey, security) as JSON for a given agent + optional task_id. Wraps `gsd-tools agent-hydrate`.",
    inputSchema={
        "type": "object",
        "properties": {
            "agent_name": {"type": "string"},
            "task_id": {"type": "string", "default": None},
        },
        "required": ["agent_name"],
    },
))
```

Handler invokes `gsd-tools agent-hydrate <agent_name> [--task-id <id>] --json` via subprocess. Returns parsed JSON verbatim (schema_version "1.0" guaranteed by Phase 47 contract).

### Area 5 — POLISH-05: Hydration auto-invoke at Task() spawn sites

EXTEND `get-shit-done/workflows/execute-phase/steps/*.md` (sharded workflow runner — Phase 41) + `get-shit-done/workflows/execute-phase-legacy.md` (legacy single-file runner) to add a single hook BEFORE each `Task(...)` invocation:

```bash
# Before spawning a subagent:
HYDRATION=$(node get-shit-done/bin/gsd-tools.cjs agent-hydrate "${AGENT_NAME}" --task-id "${TASK_ID}" --terse 2>/dev/null || echo "")
# Inject HYDRATION as a `<current_context>` block in the Task() prompt
```

Kill switch: `GSD_HYDRATE_TASKS=off` env var disables the hook (default ON).

NEW central helper in `get-shit-done/references/cli-variables.md` (precedent from LEARN-07): adds `HYDRATE_CMD="node get-shit-done/bin/gsd-tools.cjs agent-hydrate"` to the shell block.

Regression test:
- With hook ON: spawn subagent, capture prompt, assert contains `## Current context` block
- With `GSD_HYDRATE_TASKS=off`: spawn subagent, capture prompt, assert does NOT contain `## Current context` block
