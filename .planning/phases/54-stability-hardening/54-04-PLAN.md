## Goal

The Redis watchdog (`_redis_watchdog`) was committed at 48728f1 and mirrors the RLM watchdog
fix (b41ad40). The implementation is complete in source. STAB-02 closes the 2026-05-11
incident class by:

1. Writing comprehensive unit tests that verify the watchdog state machine logic in isolation
   (no real Redis needed — mock `_check_redis_health` and `_start_redis`/_stop_redis` to
   control the state machine).
2. Documenting the ~7 minute synthetic live test procedure in the test file so operators
   can run it manually when a real Redis instance is available.

The `_redis_watchdog` logic is structurally identical to `_rlm_watchdog` and is already
correct. This plan's primary output is tests that PROVE it works — not new implementation.

The 2026-05-11 incident class: Redis connection drop → `_redis_restart_count` hit max →
watchdog entered permanent silence → operator manual restart required. The watchdog fix
adds the cooldown path: after `REDIS_MAX_RESTARTS`, sleep 300s, reset counter, continue.
This plan verifies that path works.

NOTE: This plan is Wave 2 (alone in its wave) because the live test procedure involves
waiting ~7 minutes and must not block parallel tasks. The unit tests can run in CI in
seconds; the live test is documented as a manual procedure.

            """When Redis is healthy and uptime timer is None, it is set to current time."""

                    restart_count = 0
