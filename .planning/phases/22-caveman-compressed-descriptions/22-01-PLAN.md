# Plan 22-01: Caveman Description Generator + Grammar Stripper + Unit Tests

## Objective

Create the two core compression functions for Phase 22: (1) a pipe-delimited file description generator that packs function, dependencies, file patterns, test references, and quality signals into a structured format, and (2) a grammar-stripping function that removes articles, filler words, and hedging from markdown text while preserving validity. Both functions are standalone Python modules with comprehensive unit tests.

## Verification Criteria

1. `python3 -c "from services.caveman_descriptions import generate_caveman_description; print('OK')"` succeeds
2. `python3 -c "from services.grammar_strip import strip_grammar; print('OK')"` succeeds
3. `python3 -m pytest tests/test_caveman_descriptions.py -v` exits 0
4. `python3 -m pytest tests/test_grammar_strip.py -v` exits 0
5. For each of 10 test files, description matches `^.+\|.deps:.+\|.touches:.+\|.tests:.+\|.+$`
6. For each of 5 agent files, `len(strip_grammar(text)) / len(text) <= 0.70`

    **Implementation approach — static analysis, no LLM calls:**

    1. Read the file content (handle binary/unreadable gracefully — return "unreadable" fallback).
    2. Detect language from file extension (.py, .cjs, .js, .ts, .sql, .md, .json, .yaml).
    3. Extract function summary (first 10 words):
       - Python: parse first docstring or first `def`/`class` line
       - JS/CJS: parse first JSDoc comment or first `function`/`class`/`module.exports` line

       - MD: parse first heading line

       - Fallback: first non-empty, non-comment line truncated to 10 words
    4. Extract dependencies (`deps:`):
       - Python: collect `import X` and `from X import Y` — list module names, deduplicated, max 8
       - JS/CJS: collect `require('X')` and `import ... from 'X'` — list module names, max 8
       - SQL: collect `REFERENCES table` — list table names
       - Other: `deps: none`
    5. Extract file patterns touched (`touches:`):
       - Scan for string literals containing file paths (e.g., `.py`, `.cjs`, `/services/`, `/tests/`)
       - Python: look for `open(...)` calls, `Path(...)` references
       - JS: look for `fs.readFileSync`, `require('...')` with relative paths
       - Max 5 patterns
       - Fallback: `touches: self`

       - Search for files in `tests/` whose name contains the module name (e.g., `services/foo.py` -> `tests/test_foo.py`)
       - If found, count test functions (lines starting with `def test_` or `test('`)
       - Format: `tests: test_foo.py(12)` or `tests: none`
    7. Quality signal (final pipe segment):
       - Count lines of code (excluding blank lines and comments)
       - Format: `NNN loc` or `NNN loc, N exports` (count exported functions/classes)

  <action>
    Create `services/grammar_strip.py`. This module exports one primary function: `strip_grammar(text: str) -> str`.

    **Words to remove (three categories):**

    1. **Articles:** a, an, the
    2. **Filler words:** just, simply, basically, essentially, very, quite, rather, somewhat, actually, really, certainly, definitely, probably, literally, practically
    3. **Hedging phrases:** "might want to", "could potentially", "may want to consider", "it is possible that", "it should be noted that", "it is important to note that", "please note that", "keep in mind that", "you might consider", "you may want to"

    **Implementation rules:**

    1. **Preserve YAML frontmatter** (lines between `---` delimiters at file start) — strip grammar from values but not keys.
    2. **Preserve code blocks** (lines inside triple-backtick fences ``` ... ```) — do NOT strip grammar from code.
    3. **Preserve XML tags** — do NOT modify text inside `< >` tag names or attributes. DO strip grammar from text content between XML tags.
    4. **Preserve URLs** — do NOT modify text inside URLs (http://, https://, ftp://).
    5. **Preserve file paths** — do NOT modify text that looks like file paths (starts with `.`, `/`, `~`, or contains `/`).
    6. **Word boundary matching** — remove words only at word boundaries (`\bword\b`), case-insensitive.
    7. **Collapse whitespace** — after removal, collapse multiple spaces to single space. Preserve intentional newlines.
    8. **Phrase removal before word removal** — remove multi-word hedging phrases first, then single words, to avoid partial matches.
    9. **Output must be valid markdown** — headings, lists, links, bold/italic formatting must survive intact.

    **Module structure:**
    ```python
    #!/usr/bin/env python3
    """Grammar stripping for agent definitions — Phase 22 / CAVE-02.

    Removes articles, filler words, and hedging from markdown text.
    Preserves code blocks, YAML frontmatter, URLs, file paths, and XML tags.
    """

    import re
    import logging

    log = logging.getLogger("gsd.grammar_strip")

    # Word lists
    ARTICLES = {"a", "an", "the"}
    FILLER_WORDS = {"just", "simply", "basically", "essentially", "very", "quite",
                    "rather", "somewhat", "actually", "really", "certainly",
                    "definitely", "probably", "literally", "practically"}
    HEDGING_PHRASES = [
        "might want to", "could potentially", "may want to consider",
        "it is possible that", "it should be noted that",
        "it is important to note that", "please note that",
        "keep in mind that", "you might consider", "you may want to",
    ]

    def strip_grammar(text: str) -> str:
        """Strip articles, filler words, and hedging from markdown text.
        ...
        """
        # implementation

    def strip_grammar_file(path: str) -> str:
        """Read a file and return grammar-stripped content.

        Convenience wrapper for processing agent .md files.
        """
        with open(path, "r", encoding="utf-8") as f:
            return strip_grammar(f.read())
    ```

    **Key design decisions:**
    - Process text line-by-line to handle code block detection (track fenced state).
    - Use regex `re.sub(r'\b(word)\b', '', text, flags=re.IGNORECASE)` for word removal.
    - Build a single compiled regex pattern from all ARTICLES + FILLER_WORDS for efficiency.
    - Process HEDGING_PHRASES as a separate pass before single-word removal.
    - Return the stripped text, never raise.
