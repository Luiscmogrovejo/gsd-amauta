<decisions>
## Implementation Decisions

### Area 1 — Existing /amauta:help treatment

- **Brownfield: extend in place.** Keep `get-shit-done/workflows/help.md` (708 LOC). Prepend a new dynamic bearings section ABOVE the existing static reference. Single `/amauta:help` command, zero muscle-memory breakage. Static section gets a clear `## Reference` header so it's visually separable from the dynamic bearings.
- **Strict template, zero LLM interpretation.** The dynamic section is generated by code (Node) that fills a frozen Markdown template from structured query results. NO model is in the output path. Recommendation lines come from rule-based logic (e.g., `if commits_since_last_test > 3 then suggest /amauta:test-phase`). Same project state → byte-identical output. Satisfies HELP-01 verbatim.
- **Logic home: new `gsd-tools bearings` subcommand.** `node get-shit-done/bin/gsd-tools.cjs bearings [--json] [--terse]` produces structured findings + rendered Markdown. `/amauta:help` body shells out to this; `execute-phase.md`'s existing get-bearings step is updated to call the same subcommand. Single source of truth. Matches the established `route-executor`/`manifest-check`/`complexity-score` pattern in gsd-tools.cjs.

### Area 2 — Source authority + degradation

- **STATE.md is authoritative for current position** (phase, plan, status, last_activity). Honors Phase 28 BEHAV-06's "STATE = canonical snapshot" contract. Drift signals from git/PG/feature_list appear as advisory rows (e.g., `⚠ git is 3 commits ahead of STATE.md — STATE may be stale`) but do NOT override the position.
- **Graceful degradation per source** — same shape as Phase 44's per-step warn/skip:
  - PG unavailable → Pattern Stats section renders with `(unavailable — PG not reachable)` per pattern. Exit 0.
  - git unavailable (no git, no repo) → Recent Activity section renders `(unavailable — not a git repo)`. Exit 0.
  - `feature_list.json` missing for active plan → Plan Progress section renders `(no feature_list.json for active plan)`. Exit 0.
  - STATE.md missing → return exit 1 with clear error message. STATE.md is foundational; absent STATE means no project state at all.
- **feature_list.json query scope:** active plan only. Path derived from STATE.md's current phase + plan position (e.g., `.planning/phases/<phase-dir>/<plan-id>-feature_list.json`). NO milestone-wide aggregation.
- **git log scope:** last 5 commits, `--oneline`. ~120 tokens. Phase 28 BEHAV-06 used 3 at 50 tokens; this phase widens to 5 to give the recommendation engine more pattern-detection signal (e.g., "no test commits in last 5"). Token budget shift documented in the schema.

### Area 3 — Pattern types + output schema

- **Four pattern types surfaced** (HELP-02 requires ≥3 — shipping 4):
  1. **Avg sessions-per-phase-type:** `task_completions` table grouped by phase number's RPETD classification (Execute / Plan / R-P-E-T / full RPETD). Reports mean session count for current phase's class. Example output: `Avg sessions for Execute phases: 2.3 (current: 1)`.
  2. **Commits since last test run:** count of commits since the most recent successful test invocation (PG `task_completions` outcome_class='success' with task_type='test', OR filesystem mtime fallback on `tests/` dir). Example: `7 commits since last test run`.
  3. **Similar-feature session count:** pgvector cosine similarity over plan objective embeddings (reuses Phase 43 `skill_invocations` retrieval pattern). Top-K=3, cosine floor ≥0.6. Example: `Similar features avg 4.2 sessions (n=3 matches above 0.6)`.
  4. **Plan complexity score trend:** rolling average of Phase 42 SCALE-01 scores over last 3 completed plans vs current plan's score. Example: `Last 3 plans avg complexity 42/100; current plan 67/100 (above trend)`.
- **Token budget (frozen):** Phase 28 BEHAV-06's 400-token bearings budget is RAISED to **600 tokens** to accommodate pattern stats (BEHAV-06 didn't include them). New budget allocation:
  - Current position (STATE.md derived) — **100 tokens**
  - Recent activity (5 git commits + divergence-memory snippet) — **120 tokens**
  - Plan progress (active plan's feature_list.json) — **130 tokens**
  - Pattern stats (4 types, one line each) — **150 tokens**
  - Recommended next action + reasoning — **100 tokens**
  - **Overflow rule:** truncate Pattern Stats first (newest, most variable). STATE.md current position is never truncated.
- **Output schema (frozen) — structured object emitted by `--json`:**
  ```json
  {
    "schema_version": "1.0",
    "generated_at": "<ISO8601>",
    "project_state": {
      "phase_number": "45",
      "phase_name": "Intelligent Help Routing",
      "current_plan": "45-02",
      "status": "in_progress",
      "drift_signals": []
    },
    "recent_activity": {
      "commits": [{"sha": "...", "subject": "..."}],
      "divergence": {"timestamp": "...", "summary": "..."} | null
    },
    "plan_progress": {
      "feature_list_path": "<relative-path>" | null,
      "counts": {"pass": 0, "fail": 0, "pending": 0}
    },
    "pattern_stats": [
      {"name": "avg_sessions_per_phase_type", "value": "2.3", "status": "pass|warn|unavailable", "detail": "..."},
      {"name": "commits_since_last_test", "value": "7", "status": "...", "detail": "..."},
      {"name": "similar_feature_sessions", "value": "4.2", "status": "...", "detail": "..."},
      {"name": "plan_complexity_trend", "value": "67/100", "status": "...", "detail": "..."}
    ],
    "recommendation": {
      "action": "/amauta:test-phase 45",
      "reasoning": "7 commits since last test run; recommend running tests before next plan."
    }
  }
  ```
- **Markdown rendering:** the JSON object is rendered through a frozen template into the bearings block. Same template across `/amauta:help` and `execute-phase.md`. `--terse` flag drops the static-reference body (dynamic only); `--json` emits the structured object without rendering.

### Area 4 — get-bearings integration mechanism

- **Single source of truth: `gsd-tools bearings` subcommand.** Phase 28 BEHAV-06's logic (currently inlined inside `execute-phase.md`'s initialize step) moves to `node get-shit-done/bin/gsd-tools.cjs bearings`. Both `/amauta:help` and `execute-phase.md` shell out to it. NO duplication; NO bidirectional sync hell.
- **Phase 28 contract preserved:** `execute-phase.md` calls `gsd-tools bearings --terse --token-budget 400` when `feature_list.json` exists for any plan in the phase. The 400-token budget for the embedded execute-phase case is retained. `/amauta:help` uses the new 600-token budget (default).
- **Recommendation rules table** (frozen seed; rules are pure-function `(structured_findings) → {action, reasoning}`):
  - `commits_since_last_test > 3` → action `/amauta:test-phase <current-phase>`, reasoning cites the count
  - `plan_progress.counts.fail > 0` → action `/amauta:debug`, reasoning cites failing feature IDs
  - `plan_progress.counts.pending > 0 AND no fail` → action `/amauta:execute-phase <current>`, reasoning cites pending count
  - `plan_progress.counts == {pass: N, fail: 0, pending: 0} for all features` → action `/amauta:plan-phase <next>`, reasoning notes plan complete
  - `drift_signals not empty` → action `git status / review STATE.md`, reasoning cites the drift (e.g., "git 3 commits ahead of STATE")
  - Default / no data → action `/amauta:progress`, reasoning "no clear next step from current signals"
- **No registry, no cache, no LLM.** Rules table is hard-coded in `gsd-tools bearings`. Adding a rule = code change. Matches Phase 43 Area 8 (filesystem-only registry, no `help-routes.json`).

### Claude's Discretion

- Specific SQL queries against `task_completions` and `skill_invocations` (must reuse Phase 42 `_load_similar_completions` and Phase 43 `retrieve_similar` patterns — Pydantic/`_HAS_PG` import-safety fallback).
- How to detect "test run" in git log when PG is unavailable (regex on commit message, mtime on `tests/`, or both — executor's call).
- Whether `drift_signals[]` items are stringly-typed or structured (recommend `{type, severity, message}` for forward-compatibility, but not load-bearing).
- Internal rendering helper layout (`renderBearings(structuredObj, budget)` should be testable in isolation — pattern matches Phase 44's `renderStepTable`).
- Whether `--terse` is the default for `execute-phase.md`'s call or explicit (executor's call; defaulting to terse there is sane).
- Exact `divergence-memory.json` path resolution (Phase 28 already wires this).

<specifics>
## Specific Ideas

- **Schema version stamp** — `schema_version: "1.0"` on the JSON output. Forces a deliberate decision the next time the schema changes (Phase 46 MCP, Phase 47 hydration may both consume it).
- **Drift signal vocabulary** (suggested seed; refine in execution):
  - `state_git_phase_mismatch` — STATE.md says phase X, git shows commits on phase Y
  - `state_test_stale` — STATE.md last_activity > N days old with new commits
  - `feature_list_missing` — STATE.md points at plan with no feature_list.json
- **`--terse` mode** — drops Pattern Stats section + truncates Recent Activity to 3 commits. Used by execute-phase.md's 400-token call. `/amauta:help` default is full mode (600 tokens).
- **Frozen recommendation precedence order** (top-to-bottom; first match wins):
  1. fail > 0
  2. drift_signals not empty
  3. pending > 0 with no fail
  4. all pass (full plan done)
  5. commits_since_last_test > 3
  6. default
  Codified in `gsd-tools bearings` as a single ordered if/else chain. No "severity" tagging — order is the priority.

</specifics>
